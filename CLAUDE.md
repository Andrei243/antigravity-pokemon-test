# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A fan remake of Pokémon Platinum in C# (.NET 10) on Raylib-cs 8.1 (raylib 6.0), built toward the full game over many sessions. The roadmap lives in `docs/plans/` (start with `docs/plans/README.md`); the art rules live in `docs/art/style-guide.md`. Read the relevant plan before continuing roadmap work, and tick its status checklist and record decisions in it when a session ends.

The git repository is this folder. The parent folder has the same name and is not a repository; sessions often start there.

## Commands

Run from this folder.

```bash
dotnet build PokemonPlatinum.sln
dotnet test PokemonPlatinumTests
dotnet test PokemonPlatinumTests --filter "FullyQualifiedName~TestCatchRateFormula"   # one test
dotnet run --project PokemonPlatinumEngine                                             # play
dotnet run --project PokemonPlatinumEngine -- --region Sinnoh                         # new games start in Sinnoh instead of Kanto
dotnet run --project tools/DataImporter                                               # regenerate species/moves/abilities/items/trainers JSON
dotnet run --project tools/MapImporter -- [--quick] [--out <dir>]                     # Sinnoh's maps from the decompilation: pictures, world files, reports
dotnet run --project tools/MapImporter -- --data                                      # rewrite the world files the game loads (Data/world/sinnoh), after opening an area
dotnet run --project tools/ShotHarness -- <out dir> [all|field|lineup|battle|doubles|demo|arenas|flow|menus|intro|evolution|look|title|terrain|buildings|lab|life|world|times|sheets|pokemon|story|opening|jubilife|windworks|rooms|distortion] [before dir]
dotnet run --project tools/ShotHarness -- <out dir> area <key>                        # one shot of an area of the imported world (twinleaf_town, route_201…)
dotnet run --project tools/ShotHarness -- <out dir> cities [key ...]                  # every town of Sinnoh from the importer's last full run: a shot per building and prop, a sheet per town
dotnet run --project tools/ShotHarness -- <out dir> dex [--back] [species ...]        # boards of every species' 3D model (or the species and forms named), sixty to a page; --back from behind
dotnet run --project tools/ShotHarness -- <out dir> export [species ...]              # species' models as .glb files, to refine in Blender and drop into overrides/models
dotnet run --project tools/ShotHarness -- <out dir> pokemon [species ...]             # the named species' turntables on one board (91_turntables), for sculpting
dotnet run --project tools/ShotHarness -- <out dir> versus <mine> <foe> [...]         # a wild battle for each pair (species or forms), the first leading the player's party
dotnet run --project tools/ShotHarness -- <out dir> conditions                        # a battle's passing states on screen: a flight, the platform empty and the Pokémon back; a move of several hits; a Ditto transformed
dotnet run --project tools/ShotHarness -- <out dir> profile                           # where a frame goes: the heavy scenes timed and taken apart pass by pass
dotnet run --project tools/ShotHarness -- <out dir> fieldmoves                        # the field moves at work: a tree cut, a boulder pushed, a cave lit, Fly, Surf, the Pokétch, a rod
dotnet run --project tools/ShotHarness -- <dir> diff <other dir>                      # two runs' shots compared pixel by pixel: what a change did to the picture
dotnet run --project tools/ShotHarness -- <dir> contact [prefix]                      # every shot of a run on sheets of twenty
dotnet run --project tools/ShotHarness -- <dir> crop <shot> <x> <y> <w> <h> <scale> [other dir ...]   # a rectangle of a shot enlarged, beside the same of other runs
dotnet run --project tools/MusicRender -- <out dir> [song id or folder ...] [--night] [--stems]                    # songs to WAV, with level, loudness and clash checks (--sounds, --cries, --ambience for the rest)
```

- `tools/DataImporter` and `tools/MapImporter` are in the solution; `tools/ShotHarness` and `tools/MusicRender` are not, so `dotnet build PokemonPlatinum.sln` doesn't compile them. Build them too after renaming or removing engine members.
- Both importers fetch a pinned commit of the decompilation (set once, in `tools/DataImporter/Sources.cs`) into their own git-ignored `.cache` folder the first time they run. `tools/MapImporter` writes to its git-ignored `out/` folder and takes about twelve seconds; open its PNGs with the Read tool. The test project references it, so its readers are tested without the decompilation.
- The game reads and writes `savegame.json` and `settings.json` in the working directory. The harness makes `<out dir>` its working directory, so it never touches a real save.
- No linter or formatter is configured.
- This machine has no Python and no `gh` CLI. Git Bash heredocs containing apostrophes or non-ASCII text tend to fail; write such content with the Write tool.

It finds them by name alone, so none of them may be given an overload (a second `StartWildBattle` ended the `life` mode with an ambiguous match). It can't see `internal` types: `InternalsVisibleTo` covers only the test project. A battle is brought to its menu with `ToMainMenu`, which reads on past whatever lines the Pokémon's abilities say as they come in; a move is chosen only once the menu is open. The engine starts on the title screen, so the harness calls `StartNewGame()` first; only its `title` mode goes back there. A new game begins in the player's room with nothing (plan 02 · S4), so the harness then takes it past the first chapter (`PastTheOpening`: `common.OpeningDone`, a Turtwig, a few items, in front of the house), as every mode but `opening` expects.

**Two runs draw the same pictures.** The harness seeds the game's chance (`Dice.Seed`) and counts its own clock (`FrameClock.Fixed`), so a shot is the same every run and `diff` lists exactly the shots a change altered (the most changed first, with a board for each: the other run's shot, this one's, their difference eight times stronger). Before changing how anything is drawn, run the mode (or `all`) into a folder; afterwards run it again and `diff` the two, then look at what differs with `crop`. Modes carry state from one to the next (the party, the clock), so compare a mode with the same mode and `all` with `all`. Whatever is new in the engine must take its chance from `Dice` and its time from `FrameClock` or the game's own clocks: `new Random()`, `Random.Shared`, `Raylib.GetTime()` and a string's `GetHashCode()` (which changes from run to run) each make shots differ between runs. While other sessions change the same tree, the way to tell a change of the renderer from theirs is a copy: `git archive <commit> | tar -x -C <scratch>`, build its harness there (copy `cache/` from the harness's `bin` folder to skip meshing), run it for the "before", and copy only the files of the change over it for the "after". The same copy is how a change to the world's data is compared: every trainer placed draws from the game's seeded chance as the maps load, so adding people moves every battle and every later shot of `all`. Run the field modes one at a time in both trees (`field`, `world`, `terrain`, `buildings`, `lab`, `life`, `look`) and `diff` each pair.

**Where a frame goes.** `profile` (not part of `all`) times the heavy scenes (the towns and routes, a room, night, rain, fog, a battle at its menu, four moves at three moments each held still, a double battle) and then runs each with `FrameProfiler` on: a line of the milliseconds of every pass (shadows, scene, blur, bloom, occlusion, composite, interface, present, swap) with the meshes and triangles it draws, and first how long the engine took to start and how long arriving in a town not seen yet took. `SHOTS_WINDOW=3840x2160` makes the hidden window that size, which is the game full screen on a 4K display (FXAA on); `SHOTS_PRESETS=High,Medium,Low` runs the presets in turn; `SHOTS_ONLY=battle,route` keeps the scenes whose names have one of those words. About 1 ms of every frame the harness times is the hidden window's own swap of its buffers (3 ms when the window is 4K). Time nothing while a build or another harness run is going: either shows as milliseconds. Even so, readings move by two or three tenths of a millisecond from one run to the next (the harness shares the graphics card with the desktop), so judge a change by runs made back to back: before, after, before again.

The hidden window never shows the screen 1:1 or in full screen. For window problems (full screen, resizing, DPI), write a small program in the scratchpad that mirrors `Program.Main` for a few seconds and logs `GetScreenWidth/Height`, focus and window flags each frame; a full-screen window will appear on the user's display while it runs, so say so first and keep the runs few.

## Architecture

### Game loop and states

`Program.cs` opens the window and calls `GameEngine.Update(dt)` then `GameEngine.Draw()` each frame. `GameEngine` (Core) owns everything: the current `Map` and `Player`, the party, bag, Pokédex and PC storage, the active `BattleEngine`, one instance of each menu screen, and a `GameState` enum that decides which of them updates and draws. State changes that swap scenes go through `StartTransition(next, onMidpoint, kind)`: close over the scene, run the callback (load the map, create the battle), open on the next. The kind is a plain fade, or one of the ways into a battle (`SceneTransition`). `GameEngine` is one class in two files: `GameEngine.cs`, and `GameEngine.Scripts.cs` for the story's scripts ("The story and its scripts", below).

The game starts in `GameState.Title`: `TitleScreen` plays the opening and shows the menu. CONTINUE calls `ContinueGame()`; NEW GAME goes to `GameState.Intro`, where `IntroScreen` asks who the player is and who the rival is, and ends in `StartNewGame(name, look, rules, rival)`. Both load the game and fade into the field. Nothing in `currentMap`, `player` or the party is valid before one of them has run.

Saving is a question over the field (`GameState.SaveMenu`, `SaveScreen`): the engine builds the save (`BuildSave`), the screen shows its summary, and the engine writes it when the screen asks (`TakeRequest`).

Everything draws into the `virtualScreen` render texture, which is 3840×2160 and is letterboxed into the window. UI code lays out in 1920×1080 units (`VirtualWidth`, `VirtualHeight`); `Draw` wraps the 2D pass in a ×2 camera (`RenderScale`), so drawing code never multiplies by the scale itself. Sizes that must be one real pixel (anti-aliased edges) divide by `UiShapes.PixelScale`.

### Logic stays free of the GPU

Tests create `BattleEngine`, `Map`, `Pokemon` and the databases without a window, and drive battles through `SelectMainMenuOption`, `SelectMove`, `ConfirmMessage` and `Update(dt)`. Keep rules (battle flow, movement, map queries, texture baking into `PixelCanvas`) callable without raylib GPU or input calls; put drawing and key handling in separate methods.

### Battles: the rules and their face

- **The rules** are `Battle/Sim/BattleCore` (plan 06 · R2 to R7; split over `.cs` for a battle's course and the turn's order, `.Choices.cs`, `.Moves.cs`, `.Effects.cs`, `.Families.cs`, `.Unique.cs`, `.Switch.cs`, `.Turn.cs`, `.Context.cs`) and nothing else is: no screen, sound, keys or clock. It is given the two sides, a generator and the rules (`CoreSetup`), says what it waits for (`Request`: an `ActionRequest` for the Pokémon nobody inside chooses for and that isn't in the middle of a move, a `ReplacementRequest` for a place whose Pokémon fainted or, in the middle of a turn, left by its own move) and is answered in plain data (`Submit` of `BattleChoice`s). Each answer is worked out to the next question **at once**, on the Pokémon it was handed, and written into a log (`BattleLog.cs`; `Log` is all of it, `TakeLog()` what is new). A battle's course is one iterator (`Course`) that reads from top to bottom.
- **The log** is how anything gets on screen. A line (`Said`) carries what is seen as it appears (`Shows`: a lunge, the move's effect, a stat change, a condition) and what lands a moment later (`OnImpact`: the hit's damage, its sound); events between lines are things nobody reads (a ball thrown, EXP, a level, the end). The core never calls `AudioManager` or `BattleAnimator`. Something new to show is a new event there and a case in `BattleEngine.Show`.
- **The face** is `BattleEngine` (`.cs` plays the log, `.Menus.cs` turns the menus into choices): what the game, the tests and the harness use, with the public members it always had. It hands the core **copies** of every Pokémon (`BattleMirror`), because the core is a whole turn ahead of the screen: the game's own Pokémon change as the log's events are shown (a hit's damage when the hit lands). So during playback `battle.PlayerPokemon` is behind `battle.Core`'s; whenever a menu is open they are the same (`Publish`), and whatever a test or the harness changed on the game's own Pokémon meanwhile is taken over before the rules are next asked (`Adopt`). A battler's own state (confusion, a Choice lock) is copied the same way (`Battler.CopyVolatileFrom`): a new field on `Battler` or `Pokemon` that a battle changes must be added to that method or to `Pokemon.CopyStateFrom`, or the screen and the rules drift apart (`BattleCoreTests.ACopyTakesOnEverythingThatCanChange` checks every public property of `Pokemon`). The screen's state is never copied over the rules' while lines are still being shown (`playingTheLog`): a tool that hands a choice over before the menu is open must not undo what the rules worked out.
- **Who chooses**: an `IBattleController` chooses for a side from inside the core, with the battle's own numbers (the opponents' and a partner's is `TrainerAi`; `BattleCore.ControllerOf` says whose). The player's choices come from outside. A seed and the answers given are therefore the whole battle: `BattleCore.Record` is that pair (`BattleRecord`), `Replay` plays one again to the same log.
- **The trainer AI** (plan 06 · R9) is Platinum's, ported routine by routine from the decompilation's `src/battle/trainer_ai/script.s`: `Battle/Sim/Ai/AiThinking.cs` holds the script's commands as methods (scores, rolls, who is who, what the AI knows, its damage and 40ths type chart), and `AiThinking.Basic.cs`, `.Expert.cs`, `.Expert2.cs`, `.Tag.cs` and `.Flags.cs` the routines in the script's own order, quirks and bugs kept (`docs/mechanics/rulings.md` lists them). A routine asks a move by its battle effect (`MoveData.EffectId`, `MoveEffectId`, `battleEffect` in `moves.json`), never by its `effect`. `AiMemory` is what the AI has seen. `TrainerAi` is `TrainerAI_PickCommand`: a switch, an item, a move in a single or double battle, who comes in after a faint; a wild Pokémon draws a move at random. Every roll it makes is `RollKind.AiChoice` on the battle's generator. A trainer thinks with its `Trainer.Ai` flags and uses its `Trainer.Items`, both from `trainers.json` (`TrainerDatabase`).
- **Battles of their own** (`BattleKind`, `BattleCore.Special.cs`): a roamer (runs unless held), the catching lesson (the assistant's battle, which plays itself: one move, then a ball that can't fail; no misses, no critical hits; nothing reaches the player's Pokédex or team), the Great Marsh (`Safari`: no Pokémon of the player's, `ChoiceKind.Bait` and `Mud`, `SafariCatchStage` and `SafariEscapeCount`, the Pokémon's flight after each throw) and Pal Park; beside them `CoreSetup.CannotFlee`, `FirstBattle` (no critical hits) and `Partner` (a trainer filling the player's second place with a team and a mind of its own; the player loses with their own team).
- **Arithmetic** is `Battle/Sim/Formulas.cs`: Platinum's own, in whole numbers rounded down after every step, each function named for the original's (`FormulaTests` holds them against numbers worked out by hand). `DamageCalculator` and `CatchCalculator` put them in the original's order. A bonus is applied with `Formulas.Scale` in its own place, never multiplied together with others as a fraction.
- **The field and passing conditions** (plan 06 · R3): `FieldState` (`Battle/Sim/BattleField.cs`) is the weather, Trick Room, Gravity, a `SideState` for each side (screens, veils, what lies in wait) and a `PlaceState` for each place (a Wish, a Future Sight on its way). Whatever lasts while a Pokémon stays in is `Battler.Volatile` (`Volatiles`), and what holds for one turn `Battler.Turn`. They hold plain values only (a `Place`, a `MoveData`, a count), never a `Battler` or a `Move`, because the screen's battler keeps a copy (`CopyVolatileFrom`). A counter counts as the original's does and its comment says how (some end at nothing, Encore and Disable a turn end later). `Battler.Ability` is the ability in force (none under Gastro Acid): rules read that, never `Pokemon.Ability`, and `BattleEffects.Of` leaves the item out under an Embargo.
- **A move's own effect** is an entry of the table in `BattleCore.Effects.cs` (the families whose rule is a formula on the battle's numbers in `BattleCore.Families.cs`, plan 06 · R4), under the `effect` name `moves.json` gives the move, with only the parts it has (`Does` for a move that is more than a hit, `Charge`, `Start`, `Power`, `Follows`, `Reach`, `Hit`, `Then`, `Miss`; a power of the move's own `BasePower`, a fixed amount `Deals`, several `Strikes`, a hit the move decides itself `Decides`, `NoVariance`, `SelfKo`, `LeavesOneHp`). A move with no entry hits, or does what its data fields say (`ByItsFields`). After writing one, run the importer: it asks `BattleCore.HasMoveEffect` and marks the move fully run. A move runs in the original's order (the header of `BattleCore.Moves.cs`) and so does the end of a turn (`BattleCore.Turn.cs`): a new step goes where the original has it, with the function or script it was read from named beside it. `Strike` plays a move's strikes one after another on each target (`StrikeOnce`), and what a target took this turn is `Battler.Turn.Took` (the counters, Revenge, Assurance and Focus Punch read it). A move's course from "X used Y!" to what follows its hits is `Perform`; a move called by another (`CallMove`: Metronome, Sleep Talk, Me First…), bounced by Magic Coat or snatched (`UseAs`) goes through it too, and the moves of their own and the battlefield's are in `BattleCore.Unique.cs` (plan 06 · R5, R6). All 467 of Platinum's moves run in full since R6.
- **The ground** a battle is fought on is `BattleConditions.Terrain` (`BattleTerrain`: the original's thirteen, "special" for the League's rooms, the Distortion World and the Battle Frontier). `GameEngine.TerrainAt` picks it as the original does: the tile under the player first, then the area's battle background (`MapArea.BattleBackground`, from the world files' headers), then the map's stage. Camouflage, Nature Power, Secret Power and the Dive and Dusk Balls read it.
- **What a move changes for the battle alone** (Transform's shape, stats, ability and moves; Mimic's move; a copied or swapped ability; Power Trick's swap) is kept the first time in `Volatiles.Original` (`Keep`) and put back by `Revert` (`BattleCore.Switch.cs`) when the Pokémon leaves the field or the battle ends, as the original rebuilds a Pokémon's battle data from its party data; a knocked-off item is `knockedOff` until the end. A new in-battle change to a Pokémon's own fields must go through `Keep`, or it outlasts the battle through `CopyStateFrom`. A Pokémon's types in battle are `Battler.Types` and `HasType` (Conversion, Transform), never its species'; the damage formula reads them.
- **A status move is told by its category** (`MoveCategory.Status`), never by a power of 0: the original's table gives every move of variable power (Counter, Seismic Toss, Return…) the power 1, which the importer writes as 0, so Taunt and Sucker Punch ask the category, and `DamageCalculator` takes a power worked out as 0 back to 1, as the original does. `BattleCore.PayDayMoney` is what Pay Day scattered, added to the player's money with the winnings.
- **Abilities** (plan 06 · R7: all 123 of Platinum's): an ability's code is its entry in `Data/AbilityEffectTable.cs` (classes in `Battle/Effects/AbilityEffects.cs`), with three exceptions that go by the ability's **name** where the original reads it. A bonus inside the damage formula is a line of `DamageCalculator.Calculate`, in the original's own place and order (`BattleSystem_CalcMoveDamage`), never a hook: a new one goes where the original has it. What works only in the field (Pickup, Stench, Illuminate, Honey Gather, and the field side of many others) is in `Overworld/WildEncounterRules.cs` and `BattleCore.PickUp`. And the turn's own (Truant's `Loafs`, Stall, Slow Start, Unburden, Quick Feet in `EffectiveSpeed`, Normalize's `Normalized`, Lightning Rod's `Drawn`) is in the core beside the rule it changes. A held item's effect is asked for through `BattleEffects.ItemOf` (and the item itself through `ItemInHand`), which is where an Embargo and Klutz take it away.
- **What acts as a Pokémon comes in** is `BattleCore.SwitchInChecks` (`BattleCore.Switch.cs`): the original's phases in its order (the place's weather, Trace, the weather abilities, Intimidate, Download, Anticipation, Forewarn, Frisk, Slow Start, Mold Breaker, Pressure, the shapes, the held item), within a phase by Speed, each once per stay on the field (`Volatiles.Announced`, an `EntryCheck` flag each). It runs as Pokémon come in, after every action and as every turn begins, so an ability gained in the middle of things acts then (a Transform clears the flags). An ability that acts on entry needs its phase in `EntryPhases`; `BattleEffect.OnEntry` alone would run it last. `CheckShapes` gives Castform, Cherrim and Arceus their shapes (`Shapes.Take` keeps the one to give back); Arceus's type is read from its plate (`Battler.Types`).
- **Held items** (plan 06 · R8: all 158 of Platinum's): an item's code is found by its **hold effect** (`ItemData.HoldEffect`, the decompilation's name, with `HoldParam` its number), never by the item's name, so every item sharing an effect works and a new item of a known effect needs no code: `Battle/Effects/HeldItemEffects.cs` is the table of hold effects, with the hooks items answer (`AtEndOfTurn`, `AfterTheTurn`, `OnConditionChanged` for the berries and herbs, `AfterAttacking`, `EnduresHit`, the flags). A bonus inside the damage formula is a line of `DamageCalculator.Calculate` by hold effect in the original's block (`BattleEffects.HoldEffectOf`, `HoldParamOf`: the original's `Battler_HeldItemEffect`, nothing under an Embargo or with Klutz), and so are Speed's items (`EffectiveSpeed`; the halving ones are read from the item itself), accuracy's (`Hits`) and the critical-hit items (`ItemCritStages`). What the core does with items is `BattleCore.Items.cs`: the turn's order (Quick Claw, Custap Berry, Lagging Tail), the Metronome's count, the berries against a type as a hit lands, the items that answer a hit, Destiny Knot, the Amulet Coin's `PrizeMoney`, and the bag's items used in battle (`ExecuteItemUse` by the item table's use parameters, `WhyNotItem`, `CanUseInBattle`; `BattleChoice.UseItem` names the party member and the move an item is for). An item that went off this turn (`Volatiles.ItemWentOff`) is kept from an Embargo, Knock Off and Trick until its holder's move begins.
- **What may be chosen** is one place: `BattleCore.WhyNot(choice)` gives the reason a choice can't be made, `Submit` throws on one, and the menus ask it before handing a choice over (`BattleEngine.Menus.cs`). Whoever chooses from inside (`TrainerAi`) picks from `UsableMoves`.
- **After the battle** (plan 06 · R10): EXP and effort are given in `BattleCore.AwardExp` (effort first, `Models/Effort.cs`, so the levels it brings count it); a move that doesn't fit is a `MoveWanted` event and the face asks about it (`BattleEngine.Learning.cs`, `BattleMenuState.LearnMove`; `ConfirmMessage` answers so as to keep every move, and test helpers that read a battle on must treat `LearnMove` as a message). A traded Pokémon (`Pokemon.OriginalTrainer` not the player's `TrainerMark`, which `BattleConditions.Player` carries with `Badges`) obeys by `Models/Obedience.cs`. A loss's money is `BattleCore.MoneyLost`; the engine takes it and wakes the player in the last Pokémon Center (`GameEngine.WhiteOut`). Pokérus (`Models/Pokerus.cs`) and Giratina's and Arceus's forms are the engine's after every battle (`AfterBattle`, on the field's chance), Burmy's cloak the core's (`End`); `Models/FormRules.cs` holds every form rule outside battle.
- **Nothing is written after the end**: `Ended` is the log's last event (the random-battle tests hold it), so what a move tidies up afterwards must not say or emit anything once `Result` is set.
- **Testing a rule of the turn**: `BattleFieldTests`, `BattleFamilyTests`, `BattleUniqueTests` and `BattleAbilityTests` drive the bare core with both sides answered for from outside (`CoreScenario.cs`: `Wild`, `Against`, `Doubles`, `Turn`, `DoubleTurn`, `SwitchTo`, `SendIn`, `Calm()` for a battle with nothing left to chance), so a test says exactly what each Pokémon does. The faster Pokémon moves first, a move can knock its target out before the rule under test is reached, and a move's side effect is a roll (`Calm()` fixes it): each has made a scenario test something other than what it meant to test.

### Rules, chance and what is covered

- **Whose rules** (`Data/Ruleset.cs`; `docs/mechanics/rulings.md` has the table): a game is played by Platinum's rules or the modern ones, chosen on the title screen after NEW GAME (`TitlePhase.ChooseRules`), kept in the save (`SaveData.Rules`) and never changed afterwards. A battle is fought by `BattleSetup.Rules`, or by `Ruleset.Current` when it is given none. A rule that differs between the generations is read from the `Ruleset` and the difference is added there, never as a constant beside the code. `Ruleset.Use` is called by the engine alone, as a game begins or loads, before any Pokémon is made: it also swaps the moves' and the species' own values in place (`MoveData.Modern`, `PokemonSpecies.Modern` and each form's). It is static like `PlayerIdentity`, so tests must not call it: they hand rules to their battle and ask a move or a species for `Under(rules)`.
- **A battle's chance** (`Battle/Sim/BattleRandom.cs`): rolls are asked for by kind (`rng.Roll(RollKind.Accuracy, 100)`), on whatever `Random` the battle has. A `BattleRandom` is Platinum's own generator (a seed replays the same anywhere; its state is one number) and can have a kind of roll fixed (`Force`). A battle given no generator makes one, seeded from `Dice`, so the game's battles roll with it too and the harness's are the same every run. A die's faces are the original's and `RollKind` says which face is which (the damage roll's 0 is the strongest hit and 15 the weakest; paralysis holds, a thaw comes and confusion hurts on a 0). Nothing in a battle may draw from anything but the battle's generator: a roll from `Dice` or a `new Random()` inside the rules breaks every replay, which `BattleCoreTests.ARecordedBattleReplaysTheSame` would show. A test whose outcome hangs on a roll fixes it by kind, running included (it can fail now).
- **Scenario tests** (`PokemonPlatinumTests/Scenario.cs`): `Mon` (known stats), `Steady()` (no critical hits, the strongest roll, nothing misses), `Battle`, `Turn`, `Damage`. One rule to a test, the rolls it depends on fixed by kind, and the expected numbers worked out from the decompilation's code in a comment. Take the numbers from `src/battle/` of the pinned commit (`git -C tools/DataImporter/.cache/pokeplatinum show <commit>:src/battle/battle_lib.c` reads a file without changing the checkout), not from memory.
- **Coverage** (`docs/mechanics/coverage.md`, written by the data importer): every move, ability and item with how much of it runs. `CoverageTests` fails when that file isn't what the data and the engine give today, and when a number falls under its floor. So after giving a move's effect, an ability or a held item its code, run the importer and raise the floor.

### Data

Species, moves, abilities, items, trainers and maps are JSON files in `PokemonPlatinumEngine/Data/` (`species.json`, `moves.json`, `abilities.json`, `items.json`, `trainers.json`, one `maps/<Name>.json` per map), copied to the build output and read through `GameDataFiles` (camelCase names, enums as strings). The first four hold the whole National Pokédex and are generated by `tools/DataImporter` from the Platinum decompilation (Generations 1–4) and PokeAPI (later ones): don't edit them by hand; put corrections in `tools/DataImporter/Overrides/` and re-run it (`dotnet run --project tools/DataImporter`), which also rewrites `docs/mechanics/coverage.md`. A move's `effect` names what its fields can't say, and is the name the engine finds its code by (`Battle/Sim/BattleCore.Effects.cs`); moves the engine can't fully run also carry `support` (`Partial`: hits but the effect is missing; `None`: does nothing yet). A species lists its **forms** (plan 03 · D11: Mega, regional, Gigantamax, Rotom's appliances, Unown's letters; `PokemonForm`, `FormKind`), each named as Pokémon Showdown names it (`Charizard-Mega-X`, `Meowth-Galar`) and holding only what it doesn't share with its species; `PokemonDatabase.SpeciesOfForm` finds a form's species. A Pokémon in a form (`Pokemon.Form`, set by `ChangeForm`, kept in the save) takes its types, stats, abilities, learnset and size from it: read them from the Pokémon (`PrimaryType`, `HasType`, `Abilities`, `Learnset`, `Weight`, `CatchRate`), never from `Species`, and ask for its model and sprites by `ModelName`. A female of a species whose females are a form of their own (Meowstic, Basculegion, Pyroar) is in it from the start. The data also holds what later sessions write their rules from and nothing reads yet: the rest of Platinum's item table, and from Pokémon Showdown (a third pinned source) each move's power as a Z-Move and a Max Move, the Z-Moves and Max Moves themselves (`MoveKind`, never learned) and whose each Mega Stone and Z-Crystal is (Showdown also gives each form its colour). The importer leaves a file alone when its content didn't change. What abilities do is code in `Data/AbilityEffectTable.cs` (and, for a bonus in the damage formula or an effect in the field, by the ability's name where the rule is: "Battles", below), held items in `Battle/Effects/HeldItemEffects.cs`, keyed by the item's hold effect (plan 06 · R8). `PokemonDatabase`, `MoveDatabase`, `AbilityDatabase` and `ItemDatabase` load their file in a static constructor; `MapDatabase.Initialize()` reads every map file into fresh `Map` objects (new NPCs, newly rolled trainer Pokémon) through `MapFile.ToMap`, then makes the maps of the imported world (below). `MapDatabase.Get` gives the map of Sinnoh for a name it doesn't know. `docs/data-files.md` describes the formats; `MapFile.FromMap` writes a map back out, so a tool can generate map files. `TypeChart` is still code (Platinum's chart plus Fairy for later species). Maps are tile grids (`Overworld/Map`: ground layer, overhead layer, solid grid) plus NPCs, props, warps, signboards and wild encounters. What a person does when spoken to is a script (below): their own, or the common one for what their flags say they are (`IsTrainer`, `IsHealingNurse`, `IsPokeMartClerk`, `IsPCTerminal`, `IsStarterBriefcase`, `IsTransportAttendant`; `FieldScripts.For`).

Sinnoh's outdoors is the **imported world** (plan 01). `tools/MapImporter` reads the real Sinnoh from the decompilation and writes **world files** (`Data/WorldFiles.cs`; "World files" in `docs/data-files.md`): chunks of 32×32 tiles (a `TileBehavior` and a blocked flag per tile, a `TerrainCover` code for its look, height plates, props), matrices that lay chunks out in a grid (matrix 0 is the overworld), and areas with their events and land encounters. `Data/world/sinnoh/` holds what is built: `world.json` (hand-written: which matrices become maps, which areas are open), the generated files of the open areas and of the chunks in view of them (the importer's `--data`), and hand-written `overlays/<key>.json` (an area's music, where its doors lead, who its people are and our own lines for them), `habitats.json` (also `--data`), where the whole region's wild Pokémon live, open or not, for the Pokédex's area page (`Data/Habitats.cs`), and `calendar.json` (also `--data`), Platinum's weather for each day of the year in the five places that follow a calendar. To open an area: add its key to `world.json`, run `--data`, write its overlay.

`World` (`Data/World.cs`) loads that folder and `WorldMapBuilder` makes one `Map` of each matrix `world.json` lists: `Sinnoh` is the whole overworld, 960×960 tiles, so a position on it is a tile of the region and stays the same as more of it opens; each place that is a matrix of its own is a map too (`LakeVerity`, `FloaromaMeadow`, and a floor of a cave each: `OreburghGate1F`, `OreburghMineB2F`, `RavagedPath`…), reached by warps that the areas' files join by themselves. Such a map is **streamed** (`Map.IsStreamed`). Each of its chunks belongs to a `MapArea` with the name, music, wild Pokémon, trees and architecture a small map has for the whole of itself, so ask by place (`DisplayNameAt`, `BgmTrackAt`, `TreesAt`, `ArchitectureAt`, `RollWildEncounter(x, y)`, `HasLakeNear`), never the map's own properties. An area that isn't open is solid scenery, and where no chunk is loaded there is forest. `GameEngine.EnterArea` shows the name and changes the music when a step crosses into another area. Rooms and Kanto's stand-in are still hand-made map files, reached by warps (a town's Pokémon Center and Mart are rooms of its own, `OreburghPokemonCenter`, and every other door is locked until plan 01 · M11); saves made on the six hand-made maps the world replaced are moved by `SaveData.Place()`, each by the `WorldVersion` its map went with (Jubilife City's is `ImportedJubilife`).

A door can wait for the story (`"openedBy"` in an overlay's `doors`, `Warp.OpenedBy`): its tile is shut until a script sets the flag (`Map.ApplyDoors`, run with `ApplyPresence`); the door's own `read` script sets it (the Valley Windworks' Works Key, plan 02 · S6).

An overlay's people stand where the import puts them. A trainer's team is Platinum's (`res/trainers/data` in the decompilation: species, levels, and `moves` where the original chose them), the prize money its formula's, and the sight range the import's own; as the world loads, a trainer whose overlay names the same team as `trainers.json`, or none, is filled from it (`TrainerDatabase.Fill`: the AI's flags, the items, the team as the original builds it) (`AreaObject.Sight`; nought for one who battles only when spoken to). Two people can carry one trainer with one id (`doubleBattle`: Route 204's twins), and beating one beats both. Where two halves of a route list each other's people, each is placed by the half it stands in. A warp that is no door and leads nowhere yet is blocked.

**Caves** (plan 01 · M5): a map whose entry in `world.json` says `"setting": "Cave"` is rock (`TileType.CaveWall`) where the open country is forest, and so is everything that can't be come to from one of its warps (`WorldMapBuilder.CaveRock`, whose flood climbs a Rock Climb face along its grain and jumps a Bicycle's ramp as the field's rules do). An area's header may call itself a cave without being one (the lake, the meadow), which is why the setting is written there. Rock is stood up when the map is made (`RaiseRock`: two tiles above the nearest ground, a lip of three quarters right in front of open ground), in caves and outdoors alike, because the world's heights say nothing of rock nobody walks on. The mouth of a cave is its own tile (`CaveMouth`, the texture `dhole`), at the level of the ground. `Map.Camera` is the area's own camera (`FieldCamera`: default, cave, zoomed in), and `Map.IsDark` its darkness, which `Overworld/Darkness.cs` lifts once Flash has been used there (`Map.Lit`, plan 02 · S2).

**The centre** (plan 01 · M6) brought four things the world files didn't need before. A gate house with no rooms yet is walked through (`"through"` in the overlay: the warp into it comes out at the warp on its far side, `WorldMapBuilder.Join`); the Cycling Road's gates, Hearthome's to Routes 208 and 209 and to Amity Square are passed that way until plan 01 · M11 builds them. The original uses one matrix for several rooms (the Solaceon Ruins' dead ends): `world.json` makes a map for each area, and `World.MapOf` finds the one made for the area asked about. An object of the area file can be left out for now (`"heldBack"`: an item reached only through a place not open yet). And a person has a height where the original stands them above the ground (`AreaObject.Y`, `NPC.Level`: the Cycling Road's riders on the deck over Wayward Cave's way in): `Map.NpcIn(x, y, height)` is who is in the way or within speaking distance at a height, and a way in under a bridge is lowered to the ground under it, with the deck kept over it.

**The east and the sea** (plan 01 · M7). Five places take their weather from Platinum's calendar instead of their header (`calendar.json`; `MapArea.Calendar` and `WeatherOn`, read by `Map.WeatherAt` for `GameClock.Today`; `Weathers.CalendarDay` is the original's row of a date). A puddle is a look of its own (`TerrainCover.Puddle`, `TileType.Puddle`, told by its behaviour whatever its texture), and whoever stands in one is mirrored in it (`WorldRenderer.DrawReflections`, `CharacterSprites.DrawReflection`). The Great Marsh's Safari Game is `Models/SafariGame.cs` (no drawing or input): `safari start` and `safari end` in a script, `if safari`, its steps counted by `GameEngine.OnStep`, its balls handed to the Safari battle, its end the common scripts `SafariTimeUp` and `SafariOutOfBalls`, its state in the save (`SaveData.Safari`). Someone whose script warps the player (the ferry between Canalave City and Iron Island) is a way somewhere: `WorldWalk` follows a person's scripted warps as it follows warps. Iron Island's lifts are `exits` of the overlay (a warp to the other level of the same map) until platforms move. Two models of a boat whose boxes overlap (Pastoria's) each keep their side of the line between them. The ground under a bridge for bicycles is walked any way: only its deck keeps the planks' one way (`FieldMovement.Step`).

What stands on a chunk is its **models**: the original's props by their short names (`pc`, `gym00`, `t1_h01`, `funsui`). `Data/WorldModels.cs` is the catalogue of those that stand outdoors, or in a cave that is open, and what each is here: a building (its kind, the town it is built like, its storeys, the name over its door), a prop (`PropType.Fountain`, `Boat`, `WindTurbine`…), a door, or part of the ground. `WorldMapBuilder.PlaceModels` gives each its place: a building takes the tiles the world blocks under its model's box, cut into rectangles (a main block, wings, and a porch where thin pieces flank a way in), with its doors where the world's warps are; the result is `Map.PlacedBuildings`. A building whose entry says its thin pieces are conveyors (`WorldModel.Thin`: the mine's yard) has them laid as belts and gantries (`WorldMapBuilder.Conveyors`, `PropType.Conveyor` and `Gantry`, which block nothing by themselves). The importer rewrites `docs/world-models.md` from the catalogue and reports any model it doesn't know that stands outdoors or in an open cave. Fourteen models (the Battle Zone's, plan 01 · M10) have plain stand-ins until the session that builds their area (`StandInUntil`).

The importer's README says exactly what it reads from the original's files and what it never keeps.

`RegionDatabase` chains the regions in generation order: a new game starts in Kanto, and finishing a region's story (its `<Region>HallOfFame` story flag in `StoryProgress`, saved as `StoryFlags`) lets the attendant at its departure map take the player to the next region (Kanto to Johto by boat; later links are `Transport.Undecided` until their region is built). Every map belongs to exactly one region and warps never cross regions. Sinnoh is the fourth region; `--region Sinnoh` or `GameEngine.NewGameRegion` starts there for testing (in the player's room, with no Pokémon, plan 02 · S4; Kanto's stand-in start still gives a Turtwig), and saves made in Sinnoh load there.

### Walking the field

A tile's `TileType` is what it looks like; what it does is its `TileBehavior` (`Map.BehaviourAt`), which keeps Platinum's own numbers. A map of the world carries the original's value for every tile; on a hand-made map it follows from the type. `docs/tile-behaviours.md`, which the importer rewrites, lists the 94 in use with what the game does with each (`TileBehaviors.InGame`; a test keeps that table true).

- **Rules** (`Overworld/FieldMovement.cs`, no drawing or input, following the original's `src/player_move.c`): `FieldMovement.Step(map, x, y, direction, walker)` says what a step comes to (`Walk`, `Hop` over a ledge, `Jump` off a Bicycle's ramp, `Land` from the water, `Climb` up a waterfall or a rock face, or `Blocked` with the `Obstacle` that stopped it), where it ends, at what height and at what `Pace`. `Carries` says where ice or a moving floor takes someone next. A `Walker` is how they travel (`TravelMode`: on foot, surfing, cycling), the height they stand at and what the party can do (`FieldMoves`).
- **Heights**: `Map.HeightAt`, slopes for stairs, `DeckAt` for a bridge over the ground. A step of 1.25 tiles or more is a cliff. Whoever comes onto a bridge's tile stands on the deck or the ground under it, whichever is nearer their own height (`SurfaceAt`).
- **The player** (`Overworld/Player.cs`) plays the rules out: `Mode`, the height underfoot eased from tile to tile, hops, slides, `StartSurf`. `Update` reads the keys and calls `Advance`, which takes the steering as arguments, so tests and the harness walk the player without input.
- **Water is not solid**: open water is blocked for walkers by its behaviour, and `Map.IsWalkable` says so. Only a rock standing in it is a solid tile of water.
- **Wild Pokémon**: `Map.RollWildEncounter(x, y, steps, water, thick, lead)` rolls the place's land or water table by Platinum's odds (`EncounterSteps`, which the player carries and resets after a battle or a map change). The ability of the Pokémon at the head of the party (`WildLead`, which `Player.Lead` carries and the game keeps up to date) has its say in each step of it, by the original's `wild_encounters.c` (`Overworld/WildEncounterRules.cs`, no drawing or input: the rate, the row of the table, the level, whether the Pokémon is scared off, its nature, its gender). What comes back is a row of its own with the level decided and the nature and gender chosen, from which `GameEngine.StartWildBattle` makes the Pokémon.
- **Field moves** (plan 02 · S2; `Overworld/FieldMoveRules.cs`, no drawing or input): `FieldMoveRules.Check(move, spot, story)` is the original's check of a field move where the player stands (a `FieldSpot`, made by `SpotOf`): the badge Platinum asks for (`BadgeFor`: Relic for Defog and Fen for Surf, not Diamond and Pearl's), the place, a partner, what is in force already. The party menu lists each Pokémon's field moves in its own move order (`PartyScreen.ActionsFor`, with Soft-Boiled and Milk Drink's sharing of HP) and runs `common.Use<Move>`; facing an obstacle or a tile runs `CutTree`, `Rock`, `Boulder`, `RockFace`, `Waterfall` or `Water` (`GameEngine.TryInteract`), which ask the move and the badge themselves. The movement rules ask only that the move is known: going up a waterfall or a rock face also needs `Walker.Climbing`, which only a yes to the question gives (`Player.Climb`), and the way down a waterfall needs the move and no badge, as in the original. A script's `usemove` plays the move's cut-in (`UI/FieldCutIn.cs`) and makes the obstacle give way as the band closes.
- **Obstacles** are things of the map (`NPC.Obstacle`, `IsThing`; `Map.AddObstacle`), not props: a cut tree, a cracked rock or a Strength boulder stands in the way like a person and is drawn as a card (`ThingCards`, `WorldRenderer.DrawThings`). Each is hidden by a local flag of its area (below), and `Map.ResetObstacles` puts pushed boulders back. Strength, Flash and Defog are story flags (`FieldMoveRules.StrengthFlag`, `FlashFlag`, `DefogFlag`) that `GameEngine.KeepFieldMovesInForce` turns every frame into `Player.PushesBoulders`, `Map.Lit` and `Map.FogLifted`.
- **Coming to another place** (`GameEngine.ChangePlace`, on every warp and every step into another area) forgets what lasted only there, as the original does when the map's header changes: the local flags (`FLAG_MAP_LOCAL_...`, `StoryState.ClearLocal`; an obstacle's is made its area's own by `WorldMapBuilder.LocalFlag`, because one map holds many areas), Strength, Flash and Defog outside the caves, the pushed boulders, and the Bicycle where the place doesn't allow it. A warp out of the map of Sinnoh notes the way back out for Dig and an Escape Rope (`exitSpot`, saved), a Pokémon Center notes the town Teleport goes back to, and a first arrival in a town lets Fly go there (`Data/SpawnLocations.cs`, the original's twenty fly spots, by their `FLAG_FIRST_ARRIVAL_<AREA>` flags; `UI/FlyScreen.cs` is Fly's map).
- **Key items** (plan 02 · S2): the bag's USE runs an item that works in the field (`BagScreen.TakeFieldUse`: the Bicycle, the three rods, an Escape Rope), and REGISTER puts a key item on the item button (C; `SaveData.RegisteredItem`). The Bicycle's rules are `Overworld/Bicycle.cs` (where one may ride or get off: not on the Cycling Road, whose gates let only riders through, `Warp.CyclistsOnly`), and the run button changes its gear. A rod's cast is `Overworld/Fishing.cs` (`FishingAttempt`: the original's timings, and the area's rod tables, `MapArea.RodEncounters`), which `GameEngine.UpdateFishing` plays over the field. The Pokétch is `Models/Poketch.cs` (given by `poketch on`, its apps by `poketchapp`; saved), shown over the field by `UI/PoketchView.cs` (P puts it on the screen, O changes the app); only the clock, the pedometer and the team's app run so far (`Poketch.Runs`).

### The story and its scripts

Plan 02 · S1. `docs/scripts.md` is the language's reference; read it before writing a scene.

- **What the story remembers** is `Story/StoryState.cs` (GPU-free, owned by `GameEngine` as `story`): flags, integer variables, the trainers beaten, the items taken, the badges (`Badge`, in the Trainer Card's order) and the two starters. Flags and variables are named after the original's (`FLAG_...`, `VAR_...`). `Revision` counts every change. It is saved in `SaveData` (`StoryFlags`, `StoryVariables`, `DefeatedTrainers`, `TakenItems`, `Badges`, the starters, and `StoryVersion`), and `Story/StoryMigration.cs` brings a save from an older game up to date as it loads: a chapter that changes what an existing save must already know raises `StoryState.CurrentVersion` and adds its step there (version 2: a save from before the first chapter, whose game began with a Turtwig and a Pokédex, is taken past it by `common.OpeningDone`; version 3: a save from before the second is given `common.ChapterTwo`, which hides that chapter's people until their scenes and which `NewGame` calls too). `common.NewGame` is the script that sets what every game starts with; it runs with no screen (for a new game and for the oldest saves), so it may only set flags and variables, and it ends in `return`, because `OpeningDone` calls it and `end` would end that too. What the game gives as the story goes are flags as well: the Pokédex (`StoryState.PokedexFlag`, which the start menu asks before it offers POKéDEX) and the Running Shoes (`RunningShoesFlag`, `Player.HasRunningShoes`).
- **Scripts** are text files, one to a place (`Data/scripts/<area key or map name>.txt`) plus `common.txt`. `ScriptParser` reads a file into `Script`s of checked `Instruction`s and tells anything wrong with its file and line; `ScriptLibrary` holds them all (`Default` is the game's), finds a name in the place's file first and in `common` second, and lists what is wrong beyond grammar (`Problems`: an item, a species, a song, a map that doesn't exist). The lines are our own, on the original's beats.
- **The runner and its host**: `ScriptRunner` decides what happens and in what order (jumps, calls, conditions, the batch of lines that makes one talk, what a battle's outcome does to the script) and an `IScriptHost` is where it happens. The game's host is `GameEngine.FieldHost`; `HeadlessScriptHost` is a game with no screen, where everything happens at once and is written down (`Transcript`, `Asked`, `Log`, `Problems`), which is how tests play a script, or a chapter's, to its end. A new command is an `Op`, a case in the parser, a case in the runner, perhaps a method of the host (both hosts), a line in `ScriptTests.EveryCommand`, and its row in `docs/scripts.md`.
- **In the game** a script runs over the field in `GameState.Overworld` (`UpdateOverworld` hands the frame to `UpdateScript` while one is running, so the keys do nothing) and **goes on only in that state**. Whatever it starts that the player must see through changes the state (text is `GameState.Dialogue`, a battle, a screen, a warp's fade) or is something `FieldHost.Busy` reads (the script's own fade), and the runner waits for `Busy` to clear. Text closing hands the frame straight back to the script (`UpdateDialogue`), so the box doesn't blink between two talks. A question is a line of the text box that stays (`DialogueManager.ShowQuestion`) with its answers beside it in a `ChoiceBox` (`UI/Kit`, GPU-free; `ModernUi.DrawChoices`). People a script sends walking are `NpcWalk`s, the player a `PlayerWalk` (the player's own steps, with no wild Pokémon and no doors; a step that can't be taken is given up after three quarters of a second); a script's black screen is a `ScreenFade` drawn between the field and the text box.
- **What starts one** (`GameEngine.TryInteract`, `OnStep`, `EnterArea`, `FieldScripts`): talking to someone (their `Script`, or the common one for what they are; a trainer who walked up runs the same), a signboard (`common.Sign`, or `Map.SignScripts`), something read in the ground (`Map.TileScripts`, an overlay's `read`: a door, a statue), a step onto a `StepTrigger` whose variable has its value (`Map.Triggers`; an overlay gives the original's triggers their scripts by number; one in front of a warp also starts as the player comes out of it, `steppedOutOfWarp`, and one on a warp's own tile goes before the warp), and arriving somewhere (`OnEnter` in the place's file, on a warp, a loaded save or a walk across an area's border). A step across a border onto a trigger runs the place's `OnEnter` first and the trigger once it has ended (`triggerAfterEnter`), as the original runs a map's own script before its coordinate events.
- **Who moves about** (plan 02 · S6): a person of the world takes the original's movement type and range from the area file (`NPC.Movement`, `PersonMovement.Parse`), and `Overworld/Wandering.cs` (GPU-free) moves them while the field is the player's: looking about, wandering within their box, walking a loop. Nobody starts a move while a script, a trainer's walk or a menu has the field; coming to a map again puts everyone back where they first stood (`Wandering.SendHome`). The harness keeps everyone still (`GameEngine.PeopleStayPut`) but where a mode shows them moving. Someone a scene counts on finding where the import stands them is kept still by their overlay (`"still": true`).
- **Someone travelling with the player** (plan 02 · S6, `partner <who> "<trainer>"`): `Overworld/Follower.cs` walks them a step behind, onto each tile the player leaves, and `Map.Follower` keeps them out of the player's way. While they travel along, the engine heals the team after every battle not lost (`EndBattle`), meets two wild Pokémon at a time in the grass (`StartWildBattle`, `Map.MeetAnother`), brings two trainers who see the player at once together for a tag battle (`pairApproach`, `common.TrainerPair`, `pair` in a script), keeps the Bicycle, the rods, an Escape Rope and the field moves that leave the place in the bag (`FieldSpot.Partner`), and drops them on a white-out (`SetPartner`). Saved (`SaveData.Partner`, `PartnerPerson`).
- **Who is on the map**: a person may carry `HiddenBy` (a flag that takes them off the map; the world's people get the original's own from the area file) or `ShownBy`. `Map.ApplyPresence` moves people between `Map.NPCs` and `Map.Absent`, so everything that asks `NPCs` (drawing, walking, trainers' eyes) goes on as if the absent weren't there; the engine does it for every map whenever `story.Revision` has moved (`RefreshPresence`). A script's own `hide` and `show` set `NPC.Forced`, which holds until the map is come to again.
- **Items on the ground** (plan 02, after S1): an item to pick up is an `NPC` whose `NpcType` is `ItemBall` (`IsItemBall`), with its `Item`, `ItemCount` and a `HiddenBy` flag of its own. It is drawn as a Poké Ball on a card (`OutdoorProps.PaintItemBall`, `WorldRenderer.DrawItemBalls`), is in the way like a person, and runs `common.ItemBall`: `setflag own` (the flag that hides it, so it is gone for good, in this game and every save of it) and `find own`. Something hidden is a `HiddenItem` in `Map.HiddenItems`, found by looking at its tile (`FieldScripts.HiddenAt`, `common.HiddenItem`). What a script was started with is its "own": lines (`sayown`), an item (`find own`), a flag (`setflag own`); `ScriptRunner.Start` takes them, and takes an item ball's from the ball. In the imported world none of this is written by hand: `tools/MapImporter` reads what each ball and each hidden place holds from the original's item scripts and tables and writes it into the area's file (`AreaObject.Item`, `AreaSign.Item`), and `WorldMapBuilder.PlaceEvents` lays them out for every open area.
- **Local flags**: a flag named `FLAG_MAP_LOCAL_...` lasts only while the player stays in its place (`StoryState.ClearLocal`, run by `ChangePlace`), as the original's do. An obstacle's flag is one; a scene that should be undone once the player leaves can use one too.
- **Battles from scripts**: `battle self` goes through the same `StartTrainerBattle` as ever; the engine notes the outcome (`scriptOutcome`) as the battle ends and the script goes on from it once the field is back. A battle lost ends the script (the player wakes up at home) unless the script said `canlose`.

### Evolution and friendship

`docs/mechanics/evolution.md` lists every evolution method of the main games and what this game does for each; `docs/mechanics/rulings.md` records the stand-ins where the original needs hardware or a mode this game lacks. Read both before touching evolution.

- **Rules** (`Models/Evolution.cs`, no drawing or input): `Evolution.Find(pokemon, trigger, context)` says which evolution happens now and `Evolution.Evolve` carries it out. A trigger is a level-up, an item used on the Pokémon, a trade, the player spinning or the end of a battle (Sirfetch'd's critical hits); `EvolutionContext` carries what the Pokémon can't know itself (party, bag, night, dusk, rain, the map's `EvolutionSites`, the item, the species traded for, the region). The first of a species' evolutions whose condition holds wins, so their order in `species.json` matters (the importer sets it). An evolution can start from a form, lead into one or happen in one region (`fromForm`, `targetForm`, `region`); a regional form evolves only by its own (docs/mechanics/evolution.md, "Forms").
- **Never in the middle of things**: `Pokemon.GainExp` only levels up. A battle records who grew (`BattleEngine.LeveledUp`) and `GameEngine.EndBattle` asks the rules once it is over; the bag hands its evolutions over through `BagScreen.TakeEvolution`. Both end in `GameEngine.PlayEvolutions`, which queues them and fades into `GameState.Evolution`.
- **The scene** (`UI/EvolutionScreen.cs`): a function of time and three buttons (`Advance`, `PressConfirm`, `PressCancel`, `MoveCursor`), so tests drive it without a window. The species changes at the start of its `Burst` phase. Its Pokémon are rendered offscreen in `Render` (before `BeginTextureMode(virtualScreen)`, like every 3D pass) with `PokemonSprites.Render(..., flash:)`; pass the flash there, because `SetStudio` clears one set beforehand.
- **Friendship** (`Models/Friendship.cs`): Platinum's table. `GainExp` applies the level-up bonus, `GameEngine.OnStep` the walking one every 128 steps, the battle the faint penalty. `OnStep` also counts steps for the Pokémon at the head of the party, and the battle counts move uses, knock-outs, critical hits (one battle at a time), damage taken and recoil (until a faint), but only for species and forms whose evolution asks for them (`Pokemon.EvolutionProgress`).
- **Trades**: `GameEngine.ReceiveTradedPokemon(received, given)` is the single entry point for a Pokémon arriving by trade (online or from a character): it swaps it in and plays its trade evolution. Nothing calls it yet.

### Rendering

The field and battles are 3D scenes; almost every asset is generated in code at start-up (meshes, textures, character rigs, Pokémon models, sound).

- **`RenderContext`** holds the GPU resources shared by both 3D renderers: the shaders (`FieldShaders`, GLSL embedded as strings), the shadow map, the scene target with a depth texture, and the half-resolution blur, bloom and ambient-occlusion buffers. Only one 3D scene renders per frame.
- **Frame order in `GameEngine.Draw`**: the active renderer's `Render(...)` runs first (shadow pass → scene pass → `PreparePost`), then `BeginTextureMode(virtualScreen)` opens and `DrawToScreen` / `DrawField` composites the scene through the post shader, with the 2D interface drawn on top.
- **Field**: `MapStructures.BuildingsOf` gives a map's buildings: found from the tile grid on a hand-made map (their kind from where the door leads, or from the map's `buildings` list), placed by the world's models on a map of the world; `MapScene.Build` turns a `Map` into cached meshes (ground baked by `PixelGround`, water, trees, tall grass, buildings, street furniture, furnished rooms). Water is a flat surface over the ground whose shader reads a mask `PixelGround` bakes (alpha = water, red = texels from the shore). `WorldRenderer` draws it with Platinum's field camera (pitch 59.05°, FOV 16.18°, taken from the decompilation), or with the original's camera for caves or its zoomed-in one where the map says so (`MapScene.ViewOf`: every place that needs the pitch, the lens or what is in view asks it, never the outdoor constants). Characters are baked to pixel sprites (`CharacterSprites`, with pixel faces stamped by `CharacterFaces`) and drawn as lit, shadow-casting billboards. One world unit is one tile, +Z is south, and pixel art is 32 texels per unit.
- **Streaming**: a streamed map is drawn a chunk at a time. `WorldRenderer.ScenesFor` keeps the block of three chunks by three round the camera, each a `MapScene` of its own 32×32 tiles. `MapScene.Prepare(map, chunk)` bakes and packs a chunk on a worker thread; `MapScene.Uploads` hands back its GPU steps, which the renderer runs on the main thread within 2.5 ms a frame (all at once for a chunk already in view, which only happens behind a fade); chunks more than 40 tiles behind the camera are freed. `WorldRenderer.Streaming` counts the chunks a frame had to wait for.
- **Relief** (`Graphics/Relief.cs`, GPU-free; style guide, "Relief"): the heights the ground is *drawn* at, which are not the heights it is walked at. The map's `GroundLevel` is drawn at zero, so the lowlands are exactly as flat as a map without heights; water is drawn at the whole tile above its own height, level with its banks; neighbouring tiles less than 0.75 apart are joined by a slope; anything more is a face (`MapScene.AddFaces`: earth under grass, rock under rock, a deck's beams). Everything that stands on the ground asks `Relief.At` for its height: trees, grass, props, buildings, people, the camera.
- **Life** (plan 04 · G9; style guide, "Life"): what moves in the field. `FieldLife` (GPU-free; owned by `WorldRenderer`, its clock run by `GameEngine` only while the field is on screen) is told what happens (`Footstep`, `Landing`, `Splash`, `Rainfall`, `OpenDoor`, `LeaveDoor`) and gives back the quads to draw (cells of the `LifeArt` atlas, tinted) and the frame of the one door that is moving. `GameEngine.OnStep` tells it of the player's steps (`Player.JustLanded`, `JustRodeOut`); footprints follow the tile's behaviour (`TileBehaviors.KeepsFootprints`), not its look. An open door is a card (`BuildingArt.OpenDoor`) over the shut one painted on the wall, placed by `WorldRenderer.DoorPlace`. Weather is a `FieldWeather` per area (`Map.WeatherAt`, read from the area's header by `Weathers.Of`): `WeatherFx` gives what falls and the layers of mist over the picture as functions of the time, `ArtLook.Weathered` changes the light, `Weathers.Wind` the sway, and `Weathers.IsRain` is what an evolution that waits for rain asks. Art that moves in place is redrawn frame by frame: `SceneTextures.AnimateWaterfall` for the waterfalls' shared sheet, `ArtSheet.PaintFrames` and `MapScene.Animate` for a face of a map's own sheet (a fountain, a turbine). `SceneTransition` holds the shapes that close over the field and open on a battle; `ForBattle` picks among them as Platinum does (who is met, and whether their first Pokémon is of a higher level than the player's first). Three entry points are there for plan 02's scenes: `GameEngine.ShowEmote` (a bubble over anyone's head), `PanCamera` / `ReleaseCamera`, and `Steering`, which walks the player in place of the keys.
- **Field art kit**: buildings, props and furniture are boxes and upright cards whose every face is painted at its exact size. `KitBuilder` measures in texels and emits the geometry; each face is painted on first use into the map's `ArtSheet` (one texture, one batch) by a painter from `BuildingArt` (wall materials, windows, doors, signs, roof tiles, whole façades composed bay by bay, and `BuildingStyle` per kind and town), `OutdoorProps` (lamp, mailbox, planter, bench, signpost and boulder sprites; fences), `PropModels` (room furniture) or `GroundBaker` (room floors and walls). `BuildingModels` shapes the walls and roofs, porches, the tiers of the League and the stages of towers and lighthouses. `BuildingArt.StyleOf` (in `BuildingArt.Styles.cs`) picks the style: a house follows its town (fifteen `Architecture`s, each with its own walls and roof), a public building its kind (twenty-six `BuildingKind`s), and a building of the world brings its storeys, sign and porch; `BuildingArt.Kinds.cs` has the walls, windows and roof pieces the later towns need. `Landmarks` builds the props the world's models place (fountain, ship, wind turbine, statue, honey tree and the rest, and the mine's conveyors, whose belts move like a fountain's water), and ground that is built rather than grown (paving, planks, walkways, stairs) is painted tile for tile by `PixelGround`. `Pix` and `Tone` are the drawing helpers (bevels, a 5×7 alphabet, sprite outlines). All of it, like `NatureArt`, runs without GPU calls, so `BuildingTests` builds every map's kit and checks the art.
- **Characters and the SDF kit**: `SdfModel` sculpts with signed-distance shapes (smooth unions, cuts, paint, each shape with a colour, a `SurfaceMaterial` and a bone); `SdfMesher` meshes it by surface nets (only near the surface, on every core) into an indexed mesh with blended colours and up to four bone weights per vertex; `SdfCache` keeps meshes in `cache/models` next to the executable, keyed by a hash of the model. `CharacterModels` builds every character type this way (proportions, hair in locks, hats, clothes, a face patch; the normals of face and hair are softened after meshing, so the shade's edge doesn't break up over them) on a 19-bone `Skeleton`, in the background at start-up (`Preload`); `CharacterAnimation` poses it (idle, walk, run, hop, emotes, follow-through); `SkinnedModel` draws it skinned on the GPU, its outline an offset shell of the SDF. The same rig is the 3D trainer in battle (smooth face textures from `CharacterFaces`) and the source of the field sprites. `CharacterStudio` renders turntables for the harness.
- **Battle**: `BattleCore` runs the rules and `BattleEngine` plays its log as a queue of messages ("Battles: the rules and their face", above); `BattleAnimator` holds what the battle looks like at this moment (send-out, lunge, hit, faint, capture, displayed HP, and `CombatantView.Away` for a Pokémon the rules have taken out of sight in the middle of a move: it isn't drawn, and its HP box stays), the **effect cues** the engine starts (`EffectCue`: a move from one place to another and how it landed, or a stat change, heal or status on one Pokémon) and the thrown ball (`BallThrowView`, its timeline in `BallStage`). `BattleRenderer` draws, through the shots of the camera director (`BattleCamera`), the arena's stage (`BattleStage` built by `BattleArenas`, lit by `ArtLook.ArenaRig`, `SkyPainter`, ambient particles from `ArenaFx`), the trainers (who throw with the `Throw` emote), the Pokémon as 3D models from `PokemonModels`, the 3D Poké Balls (`BattleBall`) and the move effects; `BattleHUD` and `ModernUi` draw the interface.
- **Move effects**: `MoveFx` turns each cue into quads and ribbons in an `FxList`: a template per type and category, and moves with their own effect looked up by name, built from the primitives in `Fx` (streams, beams, bolts, bursts, shockwaves, auras, rain, contact flashes, slashes, orbs, waves) with shapes from the `FxTextures` atlas. Everything is a pure function of the cue's age and seed (tests check it); `FxRenderer` draws the list inside the 3D pass and `DrawField` adds the screen flash. The arena comes from the ground under the player or the map (`Map.ArenaAt`, `battleArena` in map files).
- **Pokémon**: `PokemonModels` builds a species' model with `PokeBuilder`, which sculpts with the SDF kit on a skeleton laid out by the species' `BodyPlan` (biped, quadruped, bird, serpent, fish, floating; each bone has a `PokeRole`), and meshes the body and an outline shell through `SdfCache`. 923 species are hand-built: the whole of Platinum's Sinnoh Pokédex, the 24 the story showed first - **Materials**: `SurfaceMaterials` is the table the character shaders read through the vertex's second texture coordinate (terminator width, highlight band, own light, shade tint). Material 0 is the plain look for models without ids; Pokémon use fur, scales, shell, leaf, metal and glow.
- **Look**: `ArtLook` holds the numbers of the style guide as light rigs (sun, ambient, fog, post settings, sky, how far lamps and home windows are lit) for Platinum's five times of day, blended around each boundary; rooms have rigs of their own that follow the clock through their windows, and a cave has one that ignores it (`CaveFieldRig`; ask `ArtLook.FieldRig(hour, map)`); snow country (an area with more snow than lawn, `MapArea.Snowbound`) grades the hour's rig colder (`ArtLook.Snowbound`, eased in by `WorldRenderer` at an area's border). The dark of an unlit cave is drawn over the composite (`WorldRenderer.DrawDarkness`). `GameClock` gives the hour from the system clock unless the options fix it.
- **Interface**: screens are composed from the kit. `UI/Kit` has `UiFonts` (Nunito), `UiShapes` (anti-aliased SDF panels, rings, lines, triangles), `UiIcons`, and the GPU-free `UiMotion`/`UiReveal` (easing, slide-in), `UiNav` (grid cursors) and `HeldKey` (a key kept down repeating in a long list: the Pokédex, a pocket of the bag, a shop's stock; a held step stops at the list's end where a press wraps, and `CursorTick` keeps its sound from running together). A battle's menus move their cursors in `BattleEngine.MoveCursor`, which follows the way each menu is drawn (the commands are not a grid). `ModernUi` (a partial class: shared components, `.Battle`, `.Party`, `.Field`, `.Lists`, `.Items`, `.Records`, `.Storage`, `.Intro`) holds the colour tokens and components; add a component there rather than drawing shapes in a screen. Each screen keeps its logic in methods that take no input (`StartMenu.Move/Confirm/Cancel`, `TitleScreen.PressConfirm`, `PartyScreen.MoveCursor`) so tests and the harness can drive it. The menu screens (bag, shop, Pokédex, Trainer Card, PC boxes, starter choice, saving, options; style guide, "Menu screens") share the parts in `ModernUi.Lists.cs` (`ListRow`, `Tabs`, `ScrollBar`, `Stepper`, `Money`, `SaveSummary`) and scroll with `UiNav.Window`; a list shows its screen's `VisibleRows`, which a test keeps equal to what its panel holds. What a bag item does outside battle (plan 06 · R11) is `Models/ItemUse.cs` (anything used on one Pokémon, by the item table's use parameters in the original's two passes, `WouldHelp` and `Apply`; PP Ups are `Move.PPUps`, saved and copied with the move), `Models/MoveTeaching.cs` (TMs and HMs by the species' `TmMoves`), `Models/EncounterAids.cs` (Repels and the flutes, which `WildLead` carries into the encounter rules), `Models/Evolution.cs` and `FormRules`; in battle it is `BattleCore.Items.cs` (every medicine and battle item of Platinum's, plan 06 · R8), reached through the battle's own bag (`Battle/BattleBag.cs`: the four pockets by `ItemData.BattlePocket`, and the last item used; `BattleEngine.SelectBagPocket`, `SelectBagItem`, `SelectBagTarget`, `SelectBagMove`, and `UseBagItem` for tests). A Mart's stock is `Data/MartDatabase.cs` (`marts.json`: the common counter by the badges, each town's own by its key, `NPC.Mart`, `shop "key"`); the shop asks BUY, SELL or SEE YA! first (`ShopMode`), and its `Confirm` returns what the money changes by. Dialogue is written at the options' text speed in characters a second (`DialogueManager.CharactersPerSecond`, set by `ApplySettings`), whatever the frame rate.
- **Pokédex** (plan 03 · D10): the rules are GPU-free in `Models/Pokedex.cs` (the Sinnoh and National Pokédexes with their own numbers and counts, `CanUnlockNational` after the Hall of Fame, completion and `AwardDiplomas`) and `Models/PokedexSearch.cs` (Platinum's orders, name groups, types and shapes); `Data/Habitats.cs` reads where each species lives. `PokedexScreen` keeps its state (list, entry pages, search panel, diploma) in methods that take no input; `ModernUi.Pokedex.cs` draws it. Species' regional numbers are `PokemonSpecies.SinnohNumber`.
- **Who the player is** (`Core/PlayerIdentity.cs`): the name and the look (boy or girl) chosen in the introduction, kept in the save (`SaveData.Look`, beside the trainer ID and the day the adventure began). The character the player isn't is the professor's assistant. Written text never names either: lines, people's names and a map's `displayName` say `{player}` and `{assistant}`, which `DialogueManager` and `Map.DisplayNameAt` fill in (`PlayerIdentity.Fill`); the rival's name, the introduction's last question (`PlayerIdentity.RivalName`, `SaveData.RivalName`, Platinum's own if none is typed), is `{rival}`, and a trainer of the data's `Rival` class is named so as it is filled. The `npcType`s `Player` and `Assistant` become a character through `PlayerIdentity.CharacterFor`. It is static: `StartNewGame(name, look)` and loading a save set it, and tests must not (battle tests read the default name, and test classes run in parallel); they use the overloads that take a name and a look.
- **The introduction** (`UI/IntroScreen.cs`; style guide, "The new-game introduction"): a function of its phase and its clocks (`Appearance()` gives an `IntroLook`) and four buttons (`PressConfirm`, `PressCancel`, `PressStart`, `Move`), so tests play it through. Its 3D figures (the professor, the two player characters, the Pokémon, the ball) are rendered into pictures of their own in `Render`, before `BeginTextureMode(virtualScreen)`, with `CharacterStudio.Render`, `PokemonSprites.Render` and `CharacterStudio.RenderBall`. A name is entered with `UI/Kit/NameEntry.cs` (GPU-free: the keyboard's cursor and rules) and never typed, because the game's own keys are letters.
- **Music**: songs are MML text files in `Data/music/<region>/` and `Data/music/common/`, played by our own synthesiser (`Audio/`) on raylib's audio thread, and so are the sound effects (`SoundBank`, synthesised on first use with `SoundDesign`; [`docs/sound-effects.md`](docs/sound-effects.md) lists every one, the original's sound it stands for and when it plays, and `SoundTests` holds the code to it: a sound the code names must be in the bank, and tests hear what the game plays through `AudioManager.Listen`) and every species' cry (`Cries`, from its size, name, types and family, in the original's modes; `AudioManager.PlayCry`, the same document's "Cries") and the field's ambience (`Ambience`'s looping beds of weather, water and caves, chosen where the player stands by `Overworld/FieldAmbience` and set every frame with `AudioManager.SetAmbience`; the same document's "Ambience"), all through one `AudioMixer` with a bus and a volume for the music, the fanfares, the effects, the cries and the ambience (the options set each but the fanfares', which follow the music's; `GameSettings.MusicVolume`, `SoundVolume`, `CryVolume`, `AmbienceVolume`), each bus's content held to a loudness window (`Audio/Loudness`), and an option that plays it all as the handheld's speakers would (`GameSettings.Speakers`); `docs/music-format.md` describes the format, the instruments, the mixer and the checks. Maps name their theme in `bgmTrack`; `MusicDirector` picks the riding, eye, battle, victory and fanfare themes by role, looking in the region's folder before `common` and falling back to a more general role; what a trainer class brings (its eye theme, a battle theme of its own) is `Data/audio/sound-map.json`; a wild legendary or mythical Pokémon brings its own battle theme (`Data/music/common/legendary/<key>.mml`, `MusicDirector.WildBattleTheme`). A battle theme has a low-HP arrangement (`lowhp=`, `only=lowhp`, `unless=lowhp`, `lowhptempo`) that the engine switches on mid-song while the player's Pokémon is in the red, Black and White's way rather than Platinum's beep (`AudioManager.LowHp`, `BattleEngine.PlayerInDanger`). Call `AudioManager.PlayMusic` / `PlayFanfare` / `PlaySound`, never the mixer directly. Claude can't listen: render with `tools/MusicRender` (`--sounds` for the effects, `--ambience` for the beds, `--spectrogram` for pictures of the songs), read its level, loudness, click and clash report, look at the spectrograms, and give the user MP3s to approve.
- **Measuring** (plan 04 · G11): `FrameProfiler` (off unless a tool switches it on) splits a frame into its passes; each `Lap` waits for the graphics card to finish (`Gl.Finish`), so a pass's time is the work it caused. `Core/Dice` is where the game's chance comes from when nobody hands a generator of their own, and `FrameClock` is the time the picture's small motions keep (grass, a menu icon's hop): both can be set by a tool, which is how the harness's runs repeat.
- **Leaving the game**: the start menu's QUIT GAME and the title's QUIT set `GameEngine.QuitRequested`, which ends the loop in `Program.cs`. Esc is "back", never "exit".

### Rendering rules that have caused bugs

- raylib texture modes can't nest. Every offscreen pass (field, battle stage, sprite baking, post buffers) must finish before `BeginTextureMode(virtualScreen)`.
- Matrices are built with System.Numerics (row vectors: "A then B" is `A * B`) and must be transposed for `Raylib.DrawMesh`. The light view-projection is `Raymath.MatrixMultiply(view, proj)`.
- rlgl immediate-mode batches don't set `matModel`, which the custom shaders use. Draw immediate-mode quads (speech bubbles, blob shadows) with the default shader.
- Extra samplers set with `SetShaderValueTexture` must be bound after `BeginShaderMode`; each batch flush clears them.
- `WorldRenderer` and `BattleRenderer` share `RenderContext`, so each must set its own uniforms every frame (lighting, character style, fog, time, glow, upright).
- Upright things in the field are stretched by `MapScene.VS` (1 / cos(pitch)) to offset the steep camera. Pass true proportions for the shadow pass and in battle.
- Outdoors the shared vertex shader straightens upright things (`SetUpright`): x is divided by the depth of the ground point under each vertex, and that depth becomes `w` so textures interpolate to match. Changing `gl_Position.x` alone bends textures along each quad's diagonal. Rooms, battles, sprite bakes and the shadow pass leave it at 0. Anything drawn at a height with another shader (the "!" bubble) must be moved by hand with `WorldRenderer.Straighten`; lights on the ground and halos use the `Light` program, which shares the vertex shader.
- Glass that lights up after dark is marked by alpha in the art (`ArtSheet.PublicLight` 0.8, `HomeLight` 0.6; below 0.5 is cut out), never found by colour. Write such texels with `SetRaw` or `Pix.Lit`: `PixelCanvas.Set` blends anything that isn't opaque. Paint frames and mullions afterwards, opaque, over the glass.
- A map's trees are kept in chunks of eight tiles (`MeshBatches.Chunk`) and only the chunks near the view are drawn (`WorldRenderer.VisibleRects`; shadow casters reach further toward the sun). They are drawn depth-first: a pre-pass lays down their depth with `Prepass`, then they are shaded with depth writes off, which is what keeps a forest in view within the frame budget. The vertex shader declares `invariant gl_Position` for that.
- The raylib build the game ships with (6.0, whose own GPU skinning is compiled out) binds `vertexBoneIndices` and `vertexBoneWeights` to attribute locations 7 and 8 in every shader, but its `UploadMesh` doesn't upload those buffers. `SkinnedModel.AttachBones` puts them on the mesh's vertex array itself; without it every vertex reads the default values and the whole model follows one bone. Bone matrices go to the shaders as three `vec4` rows each (`bones[]`), never through raylib's own bone uniform.
- In an `SdfModel` a cut only carves the shapes added before it, and later shapes join what's left: sculpt hair and carve its face opening before adding the head, and hem a skirt before adding the legs. Paint can be limited to some bones (`Paint(..., onBones)`) so a sleeve ends on the arm without colouring the body beside it. A shape inside the surface so far adds nothing, without any warning: hats go on the hair's surface (about 0.3 above the head's centre), not on the head (`CharacterKitTests.EveryHatShowsOverTheHair`).
- A cut carves every shape added before it, on any bone, as far as it reaches: a second bat wing's edge cuts once carved the first wing away, and a membrane trimmed to shape by big cuts left slivers that only the outline shell showed. Build thin parts to their outline instead (`BatMembrane` fills triangles with their inscribed ellipses) and keep cuts small and local (a scallop, a mouth).
- A decal on a seam between two shapes or near a surface's edge (an eye where Shieldon's face meets its shield) leaves part of its square uncovered and fails `EachDecalCoversItsWholeSquare`: put it on one smooth curve, or paint the marking (`PaintEll`).
- A direction worked out for a part (a leaf's, a spike's) must never come to nothing: `Vector3.Normalize` of a zero vector is NaN, and one NaN point throws the whole mesh out (a leaf of Fomantis's cap pointing straight down left a stray piece and its eyes uncovered).
- A spike's squash flattens it one way only, across the local z left after aligning it with its length; a fin in the plane of the body or a leaf flat to the sky comes out a blade the wrong way round, or a balloon if rounded instead. `Blade` (in `PokemonModels.Sinnoh3.cs`) takes the way its face should look.
- A thick tube through many points (a tongue) beads at every joint with the default blend, because each smooth join adds a little: join its segments with a blend of 0. Their ends meet in the same sphere, so the surface stays smooth.
- A cut has to break the surface. One wholly inside a shape leaves a hollow there: a closed piece of mesh nobody sees, which the soundness check counts as a loose part (Magmortar's bores did, until the cut reached past the barrel's end).
- Paint recolours every shape of its bone inside it. To edge an opening in one colour and show another in it, put what is inside on a bone of its own: Snorunt's face is on its head bone, the orange round it on the body's.
- Paint colours nothing on other bones, and a serpent's body is spread over many (`Coils` makes one every two points): a stripe down its length is painted a stroke on each stretch's own bone, centred on that stretch, as `Throat` does for Dratini's line. Painted on one bone, only that stretch shows it.
- A decal only takes the triangles that mostly follow its own bone (a weight of 0.3 or more). Where the head is part of the body's own shape (Happiny's line, Sudowoodo's trunk), a face given to the head bone shows nowhere or in pieces: give its eyes and marks to the bone whose shape the face is on.
- Character outlines are a separate offset shell of the SDF (`SdfCache.Get(model, cell, iso)`) drawn with front faces culled. Pushing the body out along its normals instead pokes ink through every crease (hat brims, between locks of hair).
- A colour patch that lies close under the surface it joins (a belly, a mask, a band) stays inside the smooth blend's reach and tints a wide blur round itself: make it paint (`PokeBuilder.PaintEll`), which recolours without changing the shape. Paint needs a soft edge about two mesh cells wide (`PaintEdge`), or its border follows the vertices in steps.
- Eyes and markings are decals, never shapes: anything as small as a few mesh cells comes out a blob. A decal's square must be about twice the feature (the feature fills its middle half), so the whole triangles under it cover the feature however coarse the mesh; a square that hugs the feature loses its edges.
- Models rendered on their own (sprite bakes) must call `shaders.SetStudio()` first, or fog and cloud shade from the last scene leak into them. It also clears the walkers that grass leans away from, so `WorldRenderer` calls `SetWalkers` after the sprite bakes, and `BattleRenderer` passes none.
- Vertex alpha below 1 makes scenery sway; exactly 0 (`MeshBuilder.Sway(c, 1)`) also makes it part round walkers. Tall grass, lawn tufts and flowers are in `MeshPass.Ground`, which takes shadows but casts none.
- Field art moves in whole texels: place sprites and cards on the 1/32 grid, and step animation in the water shader with `floor`, never by scrolling UVs.
- `GameEngine.ApplySettings` re-syncs the clock, mute and quality from `Settings`. Change `engine.Settings` and call it (the harness does) rather than setting `GameClock.Fixed` directly. A quality change reloads only the render targets; shaders stay loaded because cached materials refer to them.
- Full screen is `WindowSettings`' own borderless window, one row taller than the monitor. Don't use `Raylib.ToggleBorderlessWindowed` or size the window to the monitor exactly: the NVIDIA driver then treats the OpenGL window as exclusive full screen and the picture flickers.
- The virtual screen's alpha is written by its clear alone: `GameEngine.Draw` masks alpha writes (`Rlgl.ColorMask`) for the whole 2D pass and unmasks them after `EndMode2D`, because raylib's usual blending blends alpha like a colour, so every translucent panel lowered the picture's alpha and the window, which draws it over black, showed it darker than the harness's shots. A colour mask outlives the pass that set it: anything that changes it puts it back as it found it (`SceneMeshes`' depth pre-pass), and the harness warns (`!! the picture is see-through`) if a shot comes out otherwise.
- `Raylib.BeginScissorMode` takes real pixels of the target being drawn into, not layout units: the ×2 camera of the 2D pass doesn't apply to it, so a scissor given `VirtualWidth` and `VirtualHeight` clips to a quarter of the 4K picture.
- `UiFonts` loads Latin-1 only; a character outside it is drawn as "?". Signs the interface needs beyond that (the money mark, the gender marks, arrows) are drawn with `UiShapes`, not typed.
- `RenderContext.NeedsFxaa` turns FXAA on only where the window shows the scene at more than three quarters of its size (the high preset in a window wider than 2880, the medium in one wider than 2160, the low in one wider than 1440); a smaller window anti-aliases by scaling the scene down and FXAA would cost half a millisecond for nothing.
- A frame is spent filling 4K, not on geometry (plan 04 · G11; the style guide's "Quality presets" has the numbers), so a new effect is weighed by what it adds to every pixel. Measure with the harness's `profile` mode before and after; `FrameProfiler.Lap` is how a new pass gets its own line.
- A 4K texture is slow to read at scattered places: the scene's colour and depth are each read once a frame into a half-resolution copy (`RenderContext`'s `half` and `depthHalf`), and whatever needs them small (the wide blur, the glow, ambient occlusion) reads the copy. A full-screen pass clears nothing first: every pixel is written.
- The shadow map compares for itself (`Gl.CompareDepth`; the shaders read it as a `sampler2DShadow`, compiled with `HARDWARE_PCF`), and its taps stand exactly one texel apart: further apart, each tap's ramp ends before the next begins and an edge shows as steps. `Gl` is the only place that calls OpenGL past raylib; where it finds no library the shaders fall back to the rotated Poisson disc.
- Uniforms are set through `FieldShaders`' own `Set`, which keeps each location (`FieldShaders.Location`). `Raylib.GetShaderLocation` every frame is a round trip that waits for the graphics driver.
- A battle's stage lays its depth down before it is shaded (`SceneMeshes.PrepassEverything`): seen from the trainer's shoulder, one thing stands behind another all the way to the horizon. In every scene what stands on the ground is drawn before the ground.
- Baking a chunk's ground is mostly its masks (`PixelGround.Mask`): the box blur carries the sums of all columns side by side so memory is read a row at a time (a column at a time it cost five times as much), and a mask of nothing is null, not an array of zeros. `FrameTests` holds that the fast ways bake what the slow ones did, bit for bit. Chunks bake at a lower thread priority, those in view first (`WorldRenderer.Bake`).
- Battle timing: a line of the log starts what it describes as it appears (`Said.Shows`), and what it carries in `OnImpact` (a hit's damage, its sound) lands `HitDelay` after the lunge through the engine's pending effects, which `ConfirmMessage` flushes first. In the core, attach an event to the line that tells of it (`Say(...).With(...)`, `.AtImpact(...)`); an event emitted on its own happens between lines, as soon as the line before it has been read. Effects are timed to the same moment (`BattleAnimator.ImpactTime`, 0.35 s), so a new effect must land then, not when its own animation would like to. Cue seeds come from the animator, never from the battle's `Random`, so presentation can't change a battle's outcome.
- Battle effects and the ball's flashes are drawn with rlgl and the default shader inside the 3D pass (like the blob shadows). Quads marked `Depth` are depth-tested (rings round a body, ambient particles); the rest draw over the scene, so a burst at a Pokémon's middle isn't swallowed by its own body. None write depth.
- Arena walls, rock faces and rooms go in `MeshPass.Ground` (shaded and shadowed, never casting), so tall scenery can't throw the platforms into shadow. Lights an arena adds (crystals, lamps, glowing rims) are `MeshPass.Light` and drawn by `BattleStage.DrawLights` at the rig's `LampGlow`.
- Place things with `Relief.At` (or `Relief.Under` for someone who may be on a bridge), never with `Map.HeightAt`: the drawn height of water, of the lowlands and of a bank is not the walked one. Anything drawn on raised ground with the default shader (the blob shadows, the "!" bubble) also has to be moved by `WorldRenderer.Straighten`, because the ground it lies on has been.
- A river runs on under a bridge: `GroundBaker.IsWaterAt` counts a deck over water as water for the water mask and the water mesh, the deck's boards are painted over it afterwards, and the deck is drawn a hair above the water so a boardwalk level with its banks covers it. Leave any of the three out and the river is cut in two by a pond's rounded shore, or shows through the boards.
- Bright, pale ground blooms to a blank under the day light: snow and ice are kept well below white (the style guide's numbers), and the sprite shader tints white texels in shade, so effects like foam belong to the water, not to a sprite.
- A building of the world is styled by its model's town (`BuildingInfo.Town`), not by the map round it: pass `map.ArchitectureAt` to `BuildingArt.StyleOf` all the same, since a hand-made map's buildings have no town of their own. Its storeys come from the catalogue or the model's height; a tower or a lighthouse is a one-storey ground stage with its stages built on that (`BuildingModels.Stages`), so its style says one storey.
- A roof that isn't tiled is still asked for by colour: `BuildingArt.SnowRoof` and `MetalRoof` are colours that stand for the snow sheet and the ribbed metal sheet, which `BuildingArt.RoofTiles` returns for them. A style under snow has `RoofColor = SnowRoof`; don't add a flag beside it.
- An open porch (two sides and a canopy) must leave the way in open to the eye as it is to the feet: its side blocks stop where the canopy hangs, the canopy spans them, and the door is painted on the wall behind. One block over the whole porch row would hide whoever walks in. A closed porch has the door in its own front, and `BuildingArt.BaysOf` leaves the wall behind any porch tile blank.
- Tiles under a model that isn't a building's block take the ground of the tiles round them (`WorldMapBuilder.GroundLike`), so a lamp in a street stands on paving; a ship's tiles are water. Open tiles whose cover the import couldn't name do the same, or every unknown texture is a square of lawn in the paving.
- The harness's `cities` mode reads the importer's whole output, which is not in the repository: after changing `tools/MapImporter/Cover.cs` run the importer without `--quick` before judging the towns, and with `--data` to refresh what the game ships.
- Whatever the field's life is timed by uses `FieldLife.Now`, never raylib's clock: it stops while a battle or a menu covers the field, and it is a double. Weather that moves two thousand units a second multiplies that clock, and a float's steps would show as jitter after a few hours; `WeatherFx` wraps each piece's place round its own span before rounding, and a layer of mist's offset where its cloud repeats.
- An upright quad drawn with the default shader (a bubble, dust, a leaf) has each of its corners moved by `WorldRenderer.Straighten` (`DrawUpright` given the camera). Moving only its middle leaves it leaning, the more the further it stands from the middle of the screen.
- A card that is part of a wall (an open door) is drawn with the scenery's shader and a wall's normal (`CharacterSprites.MakeCard(..., partOfAWall: true)`). With the people's shader it is shaded differently from the wall round it, and its marked texels (the doorway, lit like a window) don't glow after dark.
- A face that moves has every frame the size of the face. Its sheet is rewritten with `UpdateTextureRec` before anything is drawn in the frame (`MapScene.Animate`), and its frames are kept as images with the scene and freed in `Unload`.
- Weather over the picture is drawn after the composite, in layout units, in blocks on the three-unit grid (one texel of the field at 1080p); only mist is soft (the haze texture, bilinear and repeating). What lands (rain's flecks and rings) is in the world, through `FieldLife.Rainfall`, so it stays where it fell as the camera moves.
- A door's card and a step's print are found from the player's own tiles: `Player.Heading` is where a step in progress ends, and `GameEngine` opens the door of a warp tile as soon as the player is heading for it. `FieldLife` keeps only one door moving; going through a warp clears it with everything else.
- A chunk of a streamed map is prepared on a worker thread, so `MapScene.Prepare` must not create anything on the GPU. Every shared texture it looks up has to exist already: `MapScene.Warm` makes them on the main thread first, and `SceneTextures` throws if a new one is first asked for anywhere else. Scenery that needs a new shared texture goes into `Warm` too.
- Chunks are baked alone and in any order. Anything random in the ground or on it (noise, tufts, which tree) must be seeded by the tile's place in the world, and `PixelGround` bakes two tiles past the chunk's edge and crops them off (`ChunkPad`), or the borders show as seams. `WorldTests.AChunksGroundIsTheSameHoweverMuchIsBakedWithIt` checks the ground and the water mask.
- A chunk's scene is freed with `MapScene.Unload`: its meshes and the textures baked for it. Never `UnloadMaterial` there; raylib would free the shared textures and shaders the material points at.
- A sculptor must never change its `PokeGenome`: genomes are cached and shared, and a sculpt that changes between builds changes its mesh cache key and its sprite signature. Draw anything random in a sculpt from the sculptor's own `GenomeRandom`, never `System.Random` (whose numbers may change between .NET versions).
- `PokemonModels.Get` meshes a model that isn't built yet on the calling thread (a second or more). Code that shows a species ask for it ahead with `Request` and only waits behind a fade; a frame must never be the first to ask for a model. Menus use the baked sprites, which never wait.
- Tests that change `ModelOverrides.Folders` belong to the `Model files` collection, which runs alone: every model built meanwhile would read the swapped folders.
- Rock's lip (`WorldMapBuilder.CaveLipRise`) must be no lower than `Relief.WeldLimit`. A step under three quarters of a tile is joined to its neighbours by a slope, so a lower lip made the floor beside every wall rise to meet it, and whoever walked there with it.
- What a tile under a model shows is guessed from the ground round it (`WorldMapBuilder.GroundLike`), and that guess must never be taken from a tile the import couldn't name: such a tile reads as lawn until it has taken its own ground, and put squares of lawn under coal heaps in a paved yard. Made or bare ground at a distance wins over lawn at the same distance.
- A prop a model of the world placed covers its model's box, and the world says which of those tiles block: a turbine's blades turn over grass one walks through, a conveyor spans open ground. Only props without a `Model` block every tile they cover (`Prop.IsSolid`), so code that asks "is the way blocked" asks the map, never the prop.
- The world is no longer one place with one way through it: a cave lies between Route 204's halves, rocks wait for Rock Smash, the Ironworks is reached by Surf. A test that asks whether something can be come to walks the whole game through its warps (`WorldWalk` in the test project), not one map from one tile; it passes people a new game hides until their scene comes (`WorldWalk.HiddenAtStart`: the rival on his doorstep), and a test of who stands where leaves them out.
- The old hand-made maps live on as fixtures of the art-kit tests (`Fixtures.Names`: six, Jubilife City among them). `MapDatabase.Get` of such a name gives the map of Sinnoh, so a test that means the old map asks `Fixtures`.
- Something small standing right behind the player is behind the player's own head: an upright sprite covers more than two tiles of ground beyond its feet from the field's steep camera. An item's ball one tile north of the player isn't seen at all, in the original either, so the harness looks at one from the side (`Beside` in its `story` mode), and a shot that shows nothing where a ball should be is first a question of where the player stands.
- The original numbers its hidden items by their flags, not by their place in its table: the list of flags has unused entries the table skips, so the nth entry is not hidden item n (`DecompMaps.ParseHiddenItems`). Reading it by position looked right for the first few dozen and then gave places the wrong items.
- An item's ball can stand in a passage one tile wide, and what lies beyond is reached only by picking it up: a test that asks what can be come to walks through item balls (`WorldWalk`).
- `Map.NPCs` is who is on the map now. Whatever must reach everyone the map has (saving which trainers are beaten, preloading character models, writing a map file back, finding someone for a script) asks `Map.Everyone`, or the people a flag has hidden are forgotten.
- A script's names mean the people of its own place: `Map.FindPerson(name, place)` finds nobody of another area, because the map of Sinnoh has a `clown_1` and a `pokemon_breeder_f` in more than one town and the first one found was once the wrong one, far out of sight. A script written outside the files (the harness's scene) is parsed under the name of the area it plays in.
- A script must never be left waiting on something that can't happen: a host method that starts something the player sees through has to change the game's state or set what `Busy` reads in the same call, and a walk the player can't take is given up (`PlayerWalk.GiveUpAfter`). A script that throws (`ScriptException`) is ended with a notice and the game goes on.
- Tests that play scripts on a place's map use maps of their own (`StoryTests.OwnMaps`, or `MapFile.ToMap()`): a script walks people about, beats trainers and takes people off the map, and `MapDatabase`'s maps are everybody's. `EveryWayThrough` puts people back between one way through a script and the next.
- The original's item table keeps a medicine's HP as a signed byte: all, half and a quarter are -1, -2 and -3, and a Hyper Potion's 200 is -56. The importer reads it so (`hpRestored`); read as a plain number it made a Hyper Potion take 56 HP away.
- A held item's rule lives where the original reads it, found by hold effect (`BattleEffects.HoldEffectOf`), never by the item's name: a line of the formula or the core, or a hook in `HeldItemEffects`. An item compared by name (`HeldItem?.Name == "Griseous Orb"`) is right only where the original names the item itself (Giratina's orb, the plates' species checks).
- Never bake or build the map of Sinnoh whole (`MapScene.Build`, `PixelGround.Bake(map, margin, …)`): it is 960×960 tiles and takes gigabytes. Because `MapDatabase.Get` falls back to it, code that takes a map by name can get it by accident; this is how the test run once hung. Tests that need small outdoor maps load the six old hand-made ones from `PokemonPlatinumTests/Fixtures/maps` (`Fixtures.Map`, `Fixtures.Any`).

## Project rules

- **Follow Platinum**, not Diamond/Pearl, wherever they differ (gym order, encounter tables, HM locations, music roles).
- **Platinum's rules are the default, and must not move by accident**: a game played by the modern rules is the player's choice at its start. Anything written for the modern rules goes behind the `Ruleset`, and the Platinum preset keeps giving what it gave.
- **Nothing taken from the games**: no sprites, models, textures, music, cries or script text. Art, sound and dialogue are our own; dialogue follows the original beats in our own words. Free-licensed assets (OFL, CC0, MIT) are allowed with the user's OK before downloading, and each gets a line in `docs/art/CREDITS.md`.
- **Layouts and numbers are imported; art is not.** The importers may read where things are and what they are called: tile behaviours, heights, positions, the short names of models and textures, a model's bounding box. They never write a vertex, a texture, a palette, a sound or a line of dialogue into the repository, and their caches stay git-ignored.
- **`.gitignore` ignores every folder called `overrides`** (hand-made art next to the game), except `tools/DataImporter/Overrides/`, which is re-included by name. Check `git status` after adding a file under any other `Overrides` folder.
- **Reference data**: the pret/pokeplatinum decompilation has most game data as JSON. `docs/plans/README.md` lists the paths; fetch raw files from `https://raw.githubusercontent.com/pret/pokeplatinum/main/<path>`. Bulbapedia blocks automated fetching; pokemondb.net and Serebii work.
- **Style guide first**: when a visual rule has to change, change `docs/art/style-guide.md` before the code. `StyleGuideTests` checks the rules that can be tested without a GPU.
- **Add tests for new rules** (movement, scripts, battle effects, data completeness) and keep them green.
- **Commits**: commit or push only when the user asks; commit on `main`.
