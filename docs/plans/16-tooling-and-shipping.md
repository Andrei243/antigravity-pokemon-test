# Plan 16 · Tooling and shipping

Written 2026-10-06, before any session.

**Goal**: what turns the repository into something a player downloads and a developer keeps healthy: a licence, a README and a manual with a credits screen behind them; release builds for Windows, macOS and Linux with a version and a changelog; a crash handler, a log file and command-line switches; the screenshot harness running in CI under a software renderer, with nightly runs of what is too slow for every push; live reload of the text data and a developer console; a bot that plays the open game and reports what it could not reach; a content check and a room editor for plan 01 · M11's interiors; performance budgets as tests; the harness in files with an internal facade in place of reflection; the game's state machine without its window; and, last, packs that layer over `Data/` with a manifest and a guide.

## Where we are

- **The front door**: the root holds `CLAUDE.md`, `THIRD-PARTY-NOTICES.md` and the solution. There is no `README.md`, no `LICENSE`, no changelog and no manual. `docs/art/CREDITS.md` lists the fonts and the data sources; nothing in the game shows it. `TitleChoice` is `None, Continue, NewGame, Options, Quit`, and `TitleScreen(SaveData?)` builds its `entries` from it; the style guide's "Opening and title screen" fixes the cards at CONTINUE, NEW GAME, OPTIONS, QUIT. `UiFonts` draws Latin-1 only. Plan 12 · Q15 adds the jukebox to the same menu.
- **The build**: `PokemonPlatinumEngine.csproj` is a plain `net10.0` Exe on Raylib-cs 8.1.0 (raylib 6.0) that copies `Assets`, `Data/**/*.json`, `*.mml` and `scripts/**/*.txt` to the output; no `RuntimeIdentifiers`, no single file, no self-contained publish, no version, no icon, no manifest, nothing that zips a build. `SdfCache.Folder` and `PokemonSprites.CacheFolder` are `cache/models` and `cache/sprites` under `AppContext.BaseDirectory`, so a game under Program Files or inside a read-only `.app` cannot write them. `ModelOverrides.Folders` reads `overrides/models` under the base and the current directory, `CharacterSprites.OverrideFolder` `overrides/sprites`. The save and `settings.json` are written in the working directory; plan 12 · Q1 to Q3 own them (`SavePaths`, a per-user folder, `--portable`, `--save`, a backup and a checksum, `tools/SaveTool`).
- **The program**: `Program.Main` is 53 lines: `GameSettings.Load`, `InitWindow`, `SetTargetFPS(60)`, `--region` through `RegionArgument`, then `Update`/`Draw` until `WindowShouldClose` or `QuitRequested`. There is no exception handler; `GameEngine.cs` has no `catch`; `AudioManager` and `GameSettings` report with `Console.WriteLine`; `Raylib.IsWindowFocused` is called nowhere. `FrameProfiler` (`Enabled`, `Lap`, `Report`) is switched on by the harness's `profile` mode alone. `Gl` looks up `glFinish`, `glBindTexture` and `glTexParameteri` and nothing else, so the renderer's name is never read. `GameEngine.Initialize` loads the render texture first and then the databases, `MapDatabase.Initialize`, `LoadScripts`, `CharacterModels.Preload`, `PokemonModels.Preload`, `BattleBall.Preload`, `PokemonSprites.BakeAll` and `SaveManager.LoadGame`, untimed.
- **CI**: `.github/workflows/ci.yml` is one `ubuntu-latest` job: restore, build Release, build `tools/ShotHarness`, `dotnet test`. The harness opens a hidden raylib window (`ConfigFlags.HiddenWindow`), so it never runs there. Its runs repeat (`Dice.Seed(20261004)`, `FrameClock.Fixed`), and `diff` lists what changed between two folders. Three tests wait for a schedule nobody has: `PokemonGeneratorTests.EveryGeneratedModelMeshesSoundly` under `POKEMON_MODELS_ALL=1` (plan 03 · D5), `BattleCoreTests.RandomBattlesAlwaysEndAndLeaveNothingOutOfRange`, which plan 06 · R30 wants in the thousands, and `MusicTests.TestEverySongRendersCleanly`. Plan 11's risks note that this plan's CI will mesh every rig cold.
- **The harness**: `tools/ShotHarness/Program.cs` is 3,375 lines of top-level statements. `mode` is `args[1]`, `Run(section)` picks the twenty-one sections of `all`, and the modes outside it (`area`, `cities`, `dex`, `versus`, `conditions`, `fieldmoves`, `export`, `profile`, `diff`, `contact`, `crop`) are `if` blocks. Its helpers are local functions: `Get` and `Set` on `GameEngine`'s private fields through `BindingFlags.NonPublic` (since plan 02 · S2 `flyScreen`, `poketch`, `poketchView` and `fishing` among them), `Frames`, `Skip`, `Capture`, `Shot`, `ShotCrop`, `At`, `GoTo`, `Beside`, `Confirm`, `ToMainMenu`, `Timing`, `Profile`. It calls `StartTransition`, `StartWildBattle`, `TryStartSurf`, `HandleStartMenuChoice` and `TryInteract` by name, reaches `CharacterStudio.Turntable` and `CharacterSprites.Sheet` with `GetMethod`, and cannot see `internal` types: `InternalsVisibleTo` names the test project alone. CLAUDE.md records the rule that none of those methods may take an overload.
- **Driving the game**: `GameEngine.Steering` walks the player in place of the keys, `GameEngine.Choice` is the question box, `CoreSetup.PlayerController` lets an `IBattleController` choose for the player's side (`TrainerAi.Instance` is the foe's and a partner's; since plan 06 · R9 it is Platinum's AI, which thinks only for a place with a `Trainer` behind it and draws a move at random for the player's own), `BattleEngine` has `SelectMainMenuOption`, `SelectMove`, `ConfirmMessage`, `IsWaitingForConfirm` and `Result`, and `HeadlessScriptHost` plays a script with no screen. Everything else needs the window: `UpdateOverworld` reads `InputManager` and `player.Update` reads the keys unless `Steering` is set, `Update` reads `KeyboardKey.M`, and `GameEngine` owns `RenderContext`, `WorldRenderer`, `BattleRenderer` and `virtualScreen`. `WorldWalk` (the test project) walks the whole game through its warps on the maps alone.
- **Text data is read once**: `ScriptLibrary.Default` is `shared ??= Load()` over `Data/scripts`; `LoadScripts` makes one `ScriptRunner` with the engine's `FieldHost`; `ScriptRunner.Update` runs `Execute(script.Code[at++])` with nothing watching, and an `Instruction` carries its `Op` and `Line`. `MusicLibrary.Songs` loads under `loadLock` from `MusicLibrary.Directory`. `MapDatabase.Load` reads `Data/maps/*.json` and every world `World.LoadAll` finds. The four databases load in static constructors (`Initialize()` is empty), `TrainerDatabase` reads `trainers.json` the first time a trainer is asked for (plan 06 · R9), `SoundMap` reads `audio/sound-map.json`, all through `GameDataFiles.Directory`, `PathOf` and `Load<T>`. `ModelOverrides.Refresh` is called by tools and tests only. A `ScriptException` ends a script with a notice.
- **Rooms and overlays**: twenty-one hand-made maps in `Data/maps` (`MapFile`: rows of `TileCodes`, an `InteriorStyle`), written back by `MapFile.FromMap`, which `DataFileTests.TestMapFilesRoundTripWithoutLosingAnything` holds. Fifty-four overlays in `Data/world/sinnoh/overlays` (`WorldOverlayFile`: `BgmTrack`, `Doors` as `OverlayDoor`, `Locked`, since plan 01 · M6 `Through` and `HeldBack`, people as `OverlayPerson` with a `MapFile.TrainerRecord`, triggers as `OverlayTrigger` by number) sit over area files (`WorldAreaFile`: `AreaObject` with `Id`, `Looks`, `Trainer`, `HiddenBy` and `Item`; `AreaTrigger` with `Variable` and `Value`; `AreaSign`; `AreaWarp`). The only pictures of either outside the harness are `tools/MapImporter`'s. `PixelGround.Bake(map, margin, buildings)` bakes a room's ground on the CPU, and `Bake(map, window, pad, worldSeeds, out mask)` a chunk's.
- **Measuring**: `FrameProfiler` waits for the graphics card; `FrameTests` hold that the fast bake equals the slow one, never that it stays fast; `WorldRenderer.Streaming` (`StreamingStats`: `Chunks`, `TotalUploadMs`, `WorstFrameMs`, `Waits`) is read by the harness's `world` walk; nothing times `MapScene.Prepare`, `SdfMesher.Mesh`, the static constructors, `World.LoadAll`, `ScriptLibrary.Load`, `Mml.Parse` or a save's round trip.
- **Packs**: nothing layers over `Data/`. `tools/DataImporter/Overrides/items.json` and `species.json` are the patch format already in use ("a name maps to the fields to change; a name the import doesn't have is a new item"). `.gitignore` ignores every `overrides/` folder but the importer's. Plan 05 plans `overrides/audio` (its A4 outcome leaves hand-made cries to it); plan 11 · C1 plans `Data/characters.json` as a file a mod reads.

## Design

**The user's decisions come first.** The licence, the fan-game posture, where releases go and whether a Windows runner is wanted are the user's (below); T1 and T2 wait for them.

**One build, two faces.** A player's build and a developer's are the same executable. The developer's surface (the console, the watcher, the trace) exists only under `--dev` or `Developer` in `settings.json`; off, the game reads the same files, draws the same pixels and `diff` of `all` is empty.

**One way to drive the engine.** An internal `Driver` on `GameEngine` (`Core/GameEngine.Driving.cs`) is what every tool uses to place the player, set the state, start a battle or a transition, interact, open a menu and read the game's objects. The harness, the console, the bot and the headless tests go through it, so a renamed field breaks the build instead of a run. It comes before the console and the bot because both are written on it; when T11 splits the state machine out, the `Driver` is a window on that.

**What is written about the game.** `Core/Diagnostics/` is GPU-free: a rolling log, a crash report, the start-up phases, a `GameVersion` read from the assembly. The title shows `Major.Minor.Patch` only (the commit goes in the log), so two builds of one version draw the same title and `diff` stays quiet. Nothing leaves the machine.

**CI sees the picture.** Under `xvfb` with Mesa's llvmpipe the harness runs with no card; its pixels differ from the GTX 970's, so a comparison is always between two CI runs: the PR's commit and its merge-base, built side by side as CLAUDE.md's `git archive` recipe does by hand. Determinism is checked outright: one commit run twice must `diff` to nothing.

**Tools that are GPU-free get tests; tools that draw get shots.** The content check, the budgets, the bot's policy, the console's commands, the pack layers and the editor's document are classes the test project drives. The editor's window, the console's overlay and the credits screen are drawn with the kit and shot by the harness.

**Packs layer, never replace.** `DataLayers` is a list of roots in load order read by every loader; a later root's file replaces an earlier's, a `*.patch.json` patches a data file by name. A pack-free game is byte-for-byte what it was, and a save records the packs it was played with. Platinum's defaults do not move: a pack changes what the player chose to install, and the save says so.

### T3 · Crash handler, log and switches
- `Core/Diagnostics/Log.cs`: `log.txt` beside the save, rolled at 2 MB, every `Console.WriteLine` of the engine turned into a line; `Log.Phase` round each step of `Initialize` and the first arrival in an area, which the harness's `profile` mode prints too.
- `Core/Diagnostics/CrashReport.cs` (GPU-free writer) from `AppDomain.UnhandledException` and a `try` round the loop in `Program.Main`: `logs/crash-<date>.txt` with the version and commit, OS and runtime, the renderer (`Gl.Renderer`, a new `glGetString` read, blank where `Gl.Available` is false), the settings, the `GameState`, map and tile, the last 200 lines of the log and the exception; then `savegame.crash.json` from `BuildSave` (made internal), never over the real save. The next start says so on `TitlePhase.Notice`, the line plan 12 · Q1 gives the save (the style guide's title section first).
- `Core/CommandLine.cs` (GPU-free): `--help`, `--region` (moved from `RegionArgument`), `--windowed`, `--fullscreen`, `--safe-mode` (Low, windowed 1280×720, `SdfCache.Enabled` false, overrides and packs off), `--verify` (hashes against T2's `manifest.sha256` and exits), `--log <path>`, `--dev`; plan 12 · Q2's `--portable` and `--save` join it.
- `OptionRow.FocusPause` (on: `Raylib.IsWindowFocused` false holds `playTime`, `FieldLife` and the dialogue and ducks the mixer; the harness switches it off as it does `Muted`) and `OptionRow.FrameCap` (30, 60, 120, uncapped; `SetTargetFPS` in `ApplySettings`; plan 04 · G11 left V-Sync timing alone and this is a cap only).
- Tests: the parser on every switch and on bad input; the report writer given an exception and a state writes every section; the rows cycle; the log rolls. Shots: `look_8_options`, `title` (`t*_crashed`).
- **Done when** an exception thrown in the field leaves a crash file, a crash save and a log, and the next start says the save is intact.

### T4 · CI: the harness under a software renderer, the matrix and the nightlies
- `ci.yml`: NuGet cached; `--logger trx` and a step that lists the ten slowest tests; a `shots` job on ubuntu with `xvfb` and `mesa` (`LIBGL_ALWAYS_SOFTWARE=1`, `GALLIUM_DRIVER=llvmpipe`), the harness's `cache/models` restored by `actions/cache` keyed by a hash of the model and mesher sources. The job runs `field`, `menus`, `battle` and `story` on the PR's commit and on its merge-base (a second checkout, built apart), `diff`s them, uploads the PNGs and the boards as artifacts, and fails when shots moved unless the PR carries the label `shots-change`; it also runs `field` twice on the same commit and fails when that `diff` is not empty. Timings are not read: llvmpipe's milliseconds mean nothing.
- A `windows-latest` build-and-test job if the user wants one (decision 4); `macos-latest` in the nightly.
- `nightly.yml` on a schedule: `POKEMON_MODELS_ALL=1`; `BATTLE_FUZZ=5000` read by `RandomBattlesAlwaysEndAndLeaveNothingOutOfRange` (its default stays today's count); `tools/MusicRender` over every song, `--sounds`, `--ambience` and `--cries`, failing on its clash report; `tools/MapImporter` against `Sources.DecompCommit` with its `.cache` restored and `report.md` uploaded; the harness's `all` and `dex`; T7's bot and T10's strict budgets once they exist. CONTRIBUTING.md names the required checks the user sets on `main`.
- Tests: none of the engine's; the workflow is its own check.
- **Done when** a PR that moves a drawn pixel shows its boards in the Actions summary and must say so, and a night meshes the whole dex, fuzzes thousands of battles, renders every song and imports Sinnoh.

### T10 · Performance budgets
- `BudgetTests` (its own collection): each operation run several times, the median against a budget with three times the GTX 970 machine's headroom, the figure and its date in the test: `PixelGround.Bake` of one 32×32 window and `MapScene.Prepare(map, chunk)` of it (the chunk ahead of the player must be ready before the 2.5 ms-a-frame uploads begin), `SdfMesher.Mesh` of Turtwig and of a rig, the four static constructors and `TrainerDatabase`'s first read, `World.LoadAll` with `WorldMapBuilder.Build` of Sinnoh, `MapDatabase.Initialize`, `ScriptLibrary.Load`, `Mml.Parse` of every song, a full `SaveData` round trip; `GC.GetTotalMemory(true)` after the world's maps against a ceiling. `BUDGETS=off` skips them, `BUDGETS=strict` tightens them for the nightly.
- The nightly keeps a JSON a night on a `budgets` branch and fails when tonight's median is 30 % over the month's; T3's start-up phases go into the same file when the harness runs.
- **Done when** a change that doubles the chunk bake or the species load fails the tests, and the nightly shows the month.

### T11 · The state machine without the renderers
- `Core/GameFlow.cs` (partial, GPU-free), the way plan 06 · R2 split `BattleCore` from `BattleEngine`: `GameState`, the transition's clock and callback, the menus' return states, `pendingEvolutions`, the map, the player, the party, bag, Pokédex, boxes, money, `story`, `runner`, `battle` and the screens' logic move in; it takes actions (`Steer`, `Confirm`, `Cancel`, `Menu`, `Move`) and `dt` and exposes what is on screen. `GameEngine` keeps the renderers, the window, the keys, the settings and the sound, asks the flow each frame and draws it; models wanted before a fade are an event the engine answers with `PokemonModels.Request`. `Driver` becomes the flow's own surface. Done in place, state by state, with `diff` of `all` empty at each step.
- Tests: `GameFlowTests` on the transitions, the menus' return states and the evolution queue, no window.

## Risks

- **llvmpipe at 4K is slow.** The virtual screen is 3840×2160 whatever the window; four modes may take the better part of an hour on a shared runner. If so, PRs keep build and test, the shots go nightly, and the determinism run stays on every push with `SHOTS_FILTER` narrowing it.
- **Shots never cross machines.** A CI board compared with a local run shows the renderer, not the change.
- **The split moves 3,000 lines.** T5 and T11 change no pixel on purpose, and `diff` of `all` is the proof at every step; a `BattleEngine` whose constructor plays music needs `AudioManager` to stand in headless, which `Listen` already does.
- **Dev mode reads the repository.** A release build never finds a solution above it and reads its own `Data`; a test holds that `DevMode` is off without the switch.
- **The crash save must never replace the real one**, and the report must hold no path with the user's name in it.
- **The bot can loop.** It is time-boxed, seeded and re-plans on `Revision`; a goal that fails three times is dropped and reported.
- **Budgets on shared runners are noisy.** Medians, headroom and a monthly trend, with strict numbers only on the nightly's own runner.
- **A pack changes play.** The save records it, the Platinum preset stays what it was, and the sample pack is ours; the gitignore rule for `overrides/` holds.

## Decisions for the user

1. **The licence for the code.** *Recommended:* MIT, with the fan-game notice beside it in the README (non-commercial, no affiliation, the trademarks as `THIRD-PARTY-NOTICES.md` says). Alternative: GPL-3.0, which keeps forks open, or no licence, which lets nobody redistribute.
2. **The fan-game posture.** *Recommended:* the title's notice and the README say it plainly and give a contact for takedown; no donations and no store. Alternative: no statement beyond the notice.
3. **Where releases go and what the files are called.** *Recommended:* GitHub Releases of this repository, zips named after the project and the version (`v0.y.z` until the story is complete). Alternative: a separate site, which someone has to keep.
4. **A Windows runner.** *Recommended:* yes, build and test on `windows-latest` on every push; it is the development platform and the minutes are free for a public repository. Alternative: Windows in the nightly only.
5. **Ship the mesh cache.** *Recommended:* yes, tens of megabytes for a first start of seconds. Alternative: bake at first start behind a line on the notice.
6. **An update check.** *Recommended:* none; the title shows the version and plan 07's server tells an out-of-date client. Alternative: an opt-in row that reads the releases feed.
7. **The developer's surface in a player's build.** *Recommended:* compiled in and off without `--dev`, so there is one build. Alternative: a build configuration of its own.
8. **The editor.** *Recommended:* T8's check first, T9 only when plan 01 · M11 begins. Alternative: rooms stay text edited by hand with the check and the plan pictures.
9. **Packs.** *Recommended:* T14 after T11 settles the loaders, T15 when someone wants to make one. Alternative: keep the three `overrides/` folders and no packs.
