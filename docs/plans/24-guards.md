# Plan 24 · Guards

Written 2026-10-06, before any session.

**Goal**: checks that run in the build or in `dotnet test`, need no window, and hold the game to something written down, so that what must not move can't move unnoticed: CLAUDE.md's checkable rules as build errors and architecture tests; golden files of battle logs, built trainer teams, script transcripts and a save of every version, which turn "Platinum's rules must not move by accident" into a `git diff`; strict loading of every hand-written data file, with schemas an editor reads; and a damage oracle that sets `DamageCalculator` against Pokémon Showdown's calculator, with the decompilation deciding every disagreement.

## Where we are

- **No linter**: CLAUDE.md says none is configured. There is no `Directory.Build.props`, no `.editorconfig`, no analyzer package and no `WarningsAsErrors`; `PokemonPlatinumEngine.csproj` is a plain `net10.0` Exe on Raylib-cs. The rules of CLAUDE.md's "Battles" and "Rendering rules that have caused bugs" are kept by memory, and today nearly all of them hold: the unseeded `new Random()` is only `Dice.New`'s fallback, `Random.Shared` only `Dice.Shared`'s, `Raylib.GetTime` only `FrameClock.Now`'s; `TrainerDatabase.Build` makes a `new Random(seed)` from the personality; nothing calls a string's `GetHashCode`, `HashCode`, `UnloadMaterial` or `ToggleBorderlessWindowed`. No file of `Battle/Sim`, `Battle/Effects`, `Story`, `Models` or `Data` names raylib, `AudioManager`, `InputManager`, `BattleAnimator` or `BattleEngine` but in a doc comment; in `Overworld` only `DialogueManager` uses raylib. `Graphics` calls `Map.HeightAt` only inside `Relief`, the battle code reads `Pokemon.Ability` only in `Battler.Ability`, and every engine file's namespace is its folder.
- **Three live breaks of those rules**: `UiFonts.DrawDisplayGradient` asks `Raylib.GetShaderLocation` four times a call (`UiFonts.cs`, lines 150 to 153), every frame of the title, where CLAUDE.md wants locations kept (`FieldShaders.Location`; `UiShapes` and `SkinnedModel` keep theirs at load). The diploma's day (`ModernUi.Pokedex.cs`) and the Trainer Card's "ADVENTURE STARTED" (`adventureStarted = DateTime.Now` in `StartNewGame`, drawn by `ModernUi.Records.cs`) read `DateTime.Now` instead of `GameClock.Today`, which the harness fixes through `GameClock.FixedDate` (plan 01 · M7): `menus`' `26l_pokedex_diploma` and `28_trainer_card` change from one day to the next. `PoketchView.Clock` and `GameClock.Hour` read `DateTime.Now` when nothing is fixed.
- **Sameness is checked within one run**: `BattleCoreTests.TheSameSeedAndChoicesGiveTheSameLog` and `ARecordedBattleReplaysTheSame` (the game's battle played through its menus, replayed by `BattleCore.Replay` from its `BattleRecord`) compare two logs through a private `Written` that prints events by `ToString()`, while `Entered`, `ExpGained`, `LevelRose`, `MoveWanted` and `Caught` carry a `Pokemon` by reference and `Seen` a `PokemonSpecies`. `RandomBattlesAlwaysEndAndLeaveNothingOutOfRange` plays 150 battles with teams from `new Random(battle * 7919 + 3)`, and `BattleFieldTests.BattlesFullOfTheseMovesAlwaysEndAndReplayTheSame` 240, both for invariants. `FormulaTests` and the scenario tests hold numbers worked out by hand, one rule at a time. Nothing compares a log, a line or a team with what an earlier commit gave; the harness's `diff` does it for pictures, needs a GPU and isn't in CI.
- **The one file held to what the code gives** is `docs/mechanics/coverage.md` (`CoverageTests.TheReportIsTheOneTheDataAndTheEngineGive`, with `CoverageNeverGetsWorse`'s floors); `SoundTests.TheListOfSoundsNamesEverySound` reads `docs/sound-effects.md` for every sound's name, and `FieldMovementTests.EveryBehaviourIsAccountedFor` holds the table `docs/tile-behaviours.md` prints to the rules. `CoverageTests` and `SoundTests` each find the repository with a private `Repo()` of their own. `StyleGuideTests` has two tests (the font ships, the ground is clean pixel art); `ScriptTests` (56) holds the language and `EveryCommand`.
- **Scripts**: 17 files, 1,200 lines. `StoryTests.EveryScriptOfTheGamePlaysToItsEndOnEveryWayThroughIt` plays each script every way through it (`EveryWayThrough`, private to `StoryTests`, up to 300 ways, on `StoryTests.OwnMaps`) and asserts that `HeadlessScriptHost.Problems` stays empty; the host's `Transcript`, `Asked` and `Log` are kept by nobody. `OpeningTests` plays plan 02 · S4's chapter through.
- **Trainers**: `TrainerDatabase` reads 927 trainers from `trainers.json`; `PartyOf` and `Build` make a team as `TrainerData_BuildParty` does, and `Fill` gives a map's trainer its AI flags, items and team.
- **Saves**: `SaveData.WorldVersion` (0 before the import, `ImportedWorld` 1, `ImportedJubilife` 2 = `CurrentWorld`) moves old positions through `Place()`; `StoryVersion`, up to `StoryState.CurrentVersion` 2 since plan 02 · S4, is brought up by `StoryMigration.Upgrade` (`FromBeforeTheStory`, `PastTheOpening`). `GameEngine.ApplySaveData` and `BuildSave` are private. `SaveManager` writes and reads with the serializer's defaults (property names as in C#). Old saves are tested one at a time, written inline: `WorldTests` (before the import), `SouthWestTests` (Jubilife at `ImportedWorld`), `StoryTests` (a `StoryVersion` 0 save as JSON text), `OpeningTests.ASaveFromBeforeTheChapterIsTakenToHavePlayedIt`. No save file is kept, and `.gitignore` ignores every file named `savegame.json` or `settings.json`.
- **Loading**: `GameDataFiles.Json` (camelCase, enums as names, comments, trailing commas) sets no `UnmappedMemberHandling` and is case-sensitive, so `hidenBy` or `BgmTrack` in an overlay is dropped without a word. `OneLine<T>.Read`, the converter of eleven small records of the world files (`OverlayDoor`, `OverlayTrigger`, `AreaObject` among them), reads the keys it knows and nothing else; `ImportOptions.Read` (a model's `.json`) is case-insensitive and drops the rest. The hand-written files are `world.json`, 85 overlays, 29 map files in `Data/maps`, `audio/sound-map.json`, a model's options, and the importer's two patches (`tools/DataImporter/Overrides/items.json` and `species.json`), which `Overrides.Apply` merges as `JsonNode`s and reads with `GameDataFiles.Json`: a mistyped field vanishes, and a misspelt name adds an entry. `GameDataFiles.Load` names the file of malformed JSON (`DataFileTests.TestBrokenMapFilesAreRejectedWithAClearError`, `TestMissingDataFileNamesThePath`).
- **Damage**: `DamageCalculator.Calculate(attacker, defender, move, rng, spread, …)` takes two `Battler`s with their field and applies each bonus in the original's place (plan 06 · R7, R8); `RollKind.Damage` 0 is the strongest of sixteen rolls and `BattleRandom.Force` fixes it. Pokémon Showdown is pinned for data (`Sources.ShowdownCommit`: `moves.ts`, `items.ts`, `pokedex.ts`); its calculator is a separate MIT package, `@smogon/calc` (0.12.0 on npm on 2026-10-06, from `smogon/damage-calc`). No step of the build or the tests runs node.
- **CI**: `.github/workflows/ci.yml` is one ubuntu job: restore, build Release, build `tools/ShotHarness`, `dotnet test`.

## Design

**Beside plan 16, not over it.** Plan 16 · T4 owns CI and its nightly, T5 the harness's reflection (a renamed field becomes a build error through `Driver`), T7 and T13 the fuzzers that check invariants, T8 the content check of what a loaded file means, T10 the budgets, T14 and T15 the packs. This plan adds what none of them does: an output compared with an earlier commit's, the code's own rules, the keys of a file as it is read, and the damage numbers against another program's. Every guard runs in the `dotnet test` that `ci.yml` and T4 already run; the oracle's regeneration is the one step that needs node, and it has a workflow of its own that T4's nightly also calls.

**A guard compares with something written down**: a golden file, a banned list, a schema, another calculator's rolls. When it fails it names what moved, where, and the one command that accepts the change.

**Golden files.** `PokemonPlatinumTests/Golden/` holds plain text, one event or line to a line, line endings normalised as `CoverageTests` does. `GoldenFile.Check(name, text)` reads the repository's copy (found as `CoverageTests` finds the solution), not the build output's; on a difference it writes `<name>.received.txt` beside it (git-ignored) and fails with how many blocks moved and the first of them. `GOLDEN=accept dotnet test --filter Golden` rewrites them. A session that changes a rule on purpose accepts, reads `git diff PokemonPlatinumTests/Golden` and says in its close-out which blocks moved and why; a block that moves under Platinum's rules in a session about anything else is a bug, which is the point. Every block stands alone (a battle starts with its seed, rules and teams), so a diff reads without the rest of the file, and the corpus stays small: about 200 battles, all the files under 3 MB together.

**English is the tests' language.** Logs and transcripts are English. Plan 17 · N2 moves the battle's lines into `Text.Of` with the English unchanged, so its diff of the corpus is empty, and the corpus is what proves it.

**Chance from Platinum's generator.** Corpus teams and oracle scenarios are drawn from `BattleRandom`, whose numbers are Platinum's and can't change with .NET, never from `System.Random`. Tests never call `Ruleset.Use`: whatever runs under the modern rules is built from `Under(Ruleset.Modern)` species and moves and handed `Rules = Ruleset.Modern`, and every battle is given its `Rules` and `PlayerName` rather than reading the statics.

**The decompilation decides.** The oracle is a second opinion. Each disagreement is settled against `src/battle/battle_lib.c` at `Sources.DecompCommit`: our number wrong is a fix with a scenario test whose numbers come from the decompilation; the calculator wrong, or Platinum differing from the calculator's generation 4 (which treats Diamond, Pearl, Platinum, HeartGold and SoulSilver as one), is a known difference with its reason and a row in `docs/mechanics/rulings.md`.

**Strict only where a person writes.** Hand-written files are read with unknown keys refused. Generated files and the player's own (`savegame.json`, `settings.json`) stay lenient at load, because an older save or settings file must still open; a test reads the generated files strictly, so a field renamed without re-running the importer fails there and never in a player's game.

**Allowlists say why.** Each place a banned call is allowed carries `#pragma warning disable RS0030` with its reason on the same line, and CLAUDE.md lists the places.

## Risks

- **Churn.** Every rule session of plan 06 (R11 to R30) moves golden battles; accepting and reading the diff is part of its work. A change of the log's text format rewrites the whole corpus: it goes in a session of its own with nothing else.
- **A diff too big to read.** A block per battle and an event to a line keep it local; a session that moves more than a fifth of the battles says why in a sentence per cause.
- **Allowlists that grow.** A pragma only with its reason, and CLAUDE.md lists them; a rule that needs more than three exceptions is reconsidered rather than widened.
- **IL sees calls, not intent.** A raylib call through a delegate or reflection passes; that is enough for the habits it guards.
- **The calculator's own approximations.** Expect a long known list at first; the decompilation settles each, never the calculator.
- **Node** is on CI's runners, not in the build and perhaps not on the user's machine: the answers are committed and only `oracle.yml` regenerates them.
- **Strict loading breaks a file someone has.** Only hand-written files, all in the repository and fixed in the same session; saves and settings never.
- **An open schema.** `JsonSchemaExporter` writes "anything" for a type with its own converter; the transform covers `OneLine`, and a schema an editor reads wrongly loses a convenience, not a check: the strict load is the check. If the exporter fights the enum and camelCase options, X4 leaves the schemas out and keeps the strict load.
- **Saves need the harness**, which needs a GPU, so a session writes them; plan 16 · T4 can run `saves` under llvmpipe later.

## Decisions for the user

1. **The analyzer package.** *Recommended:* `Microsoft.CodeAnalysis.BannedApiAnalyzers` (MIT, from the .NET team, build-time only, nothing shipped), RS0030 an error. Alternative: the banned calls checked by `ArchitectureTests` alone, no package, a failing test instead of a build error.
2. **The corpus's form.** *Recommended:* full text, about 200 battles and the rest, under 3 MB. Alternative: a hash per battle with the text printed on failure: tiny files, but `git diff` no longer shows what moved.
3. **Who reads a moved Platinum battle.** *Recommended:* the session explains each in its close-out and the user reads the diff of `battles-platinum.txt` before committing. Alternative: the session's explanation alone.
